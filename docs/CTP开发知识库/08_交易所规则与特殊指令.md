### 2.2 FAK / FOK 定义与实现细节

#### 2.2.1 定义
- **FOK**（立即全部成交否则自动撤销）：在限定价位下达指令，若该指令下所有申报手数未能全部成交，则全部手数自动撤销。
- **FAK**（立即成交剩余指令自动撤销）：在限定价位下达指令，若部分手数成交，剩余手数自动撤销。
  - FAK 可设最小成交数量：若可成交手数≥最小成交数量，成交后剩余撤销；若可成交手数<最小成交数量，全部撤销。
  - 不设最小成交数量：部分成交后剩余自动撤销。

#### 2.2.2 注意事项
1. FOK/FAK 应结合交易所提供的限价（或市价）指令使用。
2. FOK/FAK 不得在集合竞价时段使用。
3. 使用 FOK/FAK 造成的自成交和撤单不计入异常交易。

#### 2.2.3 示例
Cu1408 合约有 15 手 52010 元/吨卖申报、13 手 52020 元/吨卖申报，前成交价 52000，涨停 53130，跌停 48070：
- 50 手 FOK 买，报价 52020：50 手无法全部成交，全部撤销。
- 50 手 FAK 买，报价 52020：不设最小成交数量→先 52010 成交 15 手，再 52020 成交 13 手，剩余 22 手撤销；设最小成交数量 30 手→可成交 28 手<30，50 手全部撤销。

#### 2.2.4 CTP 字段组合与各所实现差异
- CTP 中用 `TimeCondition`、`VolumeCondition`、`MinVolume` 三字段表达：
  - FOK：`TimeCondition=IOC(1)` + `VolumeCondition=CV(3)`；
  - FAK：`TimeCondition=IOC(1)` + `VolumeCondition=AV(1)` 或 `MV(2)` + `MinVolume`。
- 上期所/能源中心、中金所：FAK 既支持 AV 也支持 MV（MV 时 MinVolume 生效）。
- 大商所/广期所、郑商所：FAK 用 `VolumeCondition=AV`；MV 不生效。
- 郑商所：旧资料称仅支持 FAK，6.x 文档将其特殊指令列为 FOK、IOC、GFD；以实际环境为准（工程建议：先在 SimNow 验证）。
- 郑商所 FAK 指令文件（通知号郑商函〔2014〕333）规定自 2014-12-01 起实施。

#### 2.2.5 FAK 回报时序按交易所分流
（订单初始均为 OnRtnOrder“未知单”状态 'a'）

| 所族 | 回报顺序（部分成交、剩余撤单） |
|---|---|
| 上期所 / 能源中心 / 中金所 | 先收到**撤单状态**回报 `OnRtnOrder(已撤单, VolumeTraded 已有值)`，随后每笔成交 `OnRtnOrder(已撤单)` + `OnRtnTrade`；不会有部分成交 '1' 状态 |
| 大商所 / 广期所 | `OnRtnOrder(未成交)`（CTP 补充，不管会不会立即成交，进入报单簿后都有一笔未成交回报）→ 成交 `OnRtnOrder(部分成交)` + `OnRtnTrade` → `OnRtnOrder(已撤单)`；不重复推送前一状态 |
| 郑商所 | `OnRtnOrder(未成交)` → 成交时 `OnRtnOrder(未成交)`（前一状态）+ `OnRtnOrder(部分成交)` + `OnRtnTrade` → `OnRtnOrder(已撤单)` |

要点：
- 上期所组：撤单行先于成交行到达；若客户端“收到终态 '5' 就认为订单已死”会丢掉后续 OnRtnTrade；若“靠 '1' 累加成交量”会漏算——应以 `OnRtnTrade` 为成交量真值（工程建议）。
- 郑商所每笔成交有前态+新态两条 OnRtnOrder，按状态行计次会重复。
- FAK 全部成交时无专门规定，按一般规则（未知单→未成交→全部成交 + OnRtnTrade）；FOK 与市价单永不进簿（无“未成交”行）。
- 终态撤单是交易所主动撤剩余量，不带前态重复；与客户端主动撤单形状不同。
- 状态没变就不重复推（大商所规则的一般化）。

### 2.3 市价单与止损止盈

- 上期所：市价单需保护价；转限价需 `TimeCondition=GFD,VolumeCondition=AV`。
- 大商所：市价单价格填 0；止损触发条件为最新价>/<触发价（CTP 为 `StopPrice`）时触发新报单，新报单可为市价或限价；买止损平仓/卖止损平仓是多年前提出的概念，从未实施。
- 中金所：市价类（最优价/五档价）及转限价。
- 郑商所：市价指令，套利指令，另有 FAK（FOK 视环境）。
- 组合合约（套利合约）不支持市价单（行情无有效最新价）。
- 条件单（CTP 本地条件单）规则见对应 API 页面“条件单规则”，`ContingentCondition` 枚举见《15_枚举常量速查表》。

### 2.4 平今平昨规则与手续费
- 上期所/能源中心区分今仓、昨仓：平仓指令需明确 `THOST_FTDC_OF_CloseToday('3')` 或 `CloseYesterday('4')`；若报 `Close('1')`，CTP 按平昨处理（行权指令同理）。
- 大商所、郑商所、中金所：平仓使用 `Close('1')`，也可用 `CloseToday`（以实际环境为准）；大商所、郑商所平仓默认先平昨。
- 平今手续费通常高于平昨：以 `ReqQryInstrumentCommissionRate` 返回 `CloseTodayRatioByMoney/ByVolume` 为准，计算见《资金与手续费》章节。
- 上期所平今仓位冻结只影响今仓可平量（对应 `TodayPosition`、`YdPosition`、`CloseTodayVolume`）。
- 中金所股指期货平今手续费有特别规定，以费率查询为准（工程建议）。

#### 2.5.2 不计入统计的情形
- 上期所/中金所：FOK、FAK 形成的自成交和撤单不计入。
- 大商所/郑商所：市价指令、止损（盈）指令、套利指令、附加 FOK/FAK 属性形成的撤单和自成交不计入。
- 套利交易、套保交易产生的自成交、频繁报撤单、大额报撤单不作为异常交易行为。

#### 2.5.3 处理程序（大商所办法，其他所类似）
**客户**：
1. 第一次达到处理标准：交易所当日对客户所在会员首席风险官电话提示；（风险提示、客户写承诺书）
2. 第二次：列入重点监管名单，向期货公司通报（客户写情况说明）；
3. 第三次：闭市后限制开仓，**不低于 1 个月**。

**非期货公司会员**：第一次电话提示指定联系人；第二次约见高级管理人员谈话；第三次限制开仓**不低于 3 个月**。

**实际控制关系账户合并持仓超限**：
- 完全由客户构成：当日闭市后通知会员首席风险官，要求自行平仓；次日第一节前未平，交易所强行平仓至不超限，并限制开仓不低于 1 个月。
- 一组账户出现：第一次列入重点监管；第二次次日限制开仓不低于 10 个交易日；第三次限制开仓不低于 6 个月。
- 当日结算时持仓未超过上一交易日结算时的持仓限额，可豁免第二项；当日已强平的账户组在同合约同方向继续超限，若当日未在该方向增仓，可豁免。
- 实际控制关系账户自成交、频繁报撤单、大额报撤单情节恶劣的，不受次数限制，交易所可直接依据违规处理办法给予警告、强行平仓等纪律处分（郑商所）。

**对期货公司会员**：客户行为发生在同一会员的，电话提示该会员；不同会员的，选择该类行为次数最多的会员提示；会员须转达并教育、劝阻客户。未尽义务的，可提示、约见谈话、监管警示函；已发二次警示函的，第三次下发监管意见函并提请分类监管扣分。

#### 2.5.4 其他异常交易行为
- 通过计算机程序自动批量下单、快速下单影响交易所系统安全或正常交易秩序（上期所/郑商所）。
- 影响交割结算价行为（对倒、对敲使交割月合约价格异常波动达涨跌停板幅度 40% 以上）。
- 盗码交易；自然人客户违规持仓（交割月前一月最后一个交易日闭市时仍保留该交割月份持仓）。
- 大笔申报、连续申报、密集申报，或申报价格明显偏离最新成交价，可能影响期货交易价格；日内频繁回转交易；大量或多次高买低卖。
- 中国证监会或交易所认定的其他情形。

### 2.6 程序化交易与高频报备、穿透式监管
- 终端须通过穿透式监管认证：登录前以 `ReqAuthenticate` 提交 `AppID`、`AuthCode`（认证通过后才能登录），终端信息采集库随 API 提供；中继（转发）类终端须通过 `RegisterUserSystemInfo` 上报终端用户信息，其中 `ClientPublicIP`、`ClientAppID`、`MAC` 须规范填写，`ClientLoginRemark` 建议格式“UUID|手机号..”，均填写终端投资者本人的信息；后续这三个字段可能由非必填改为必填。详见《登录认证与流控》相关章节。
- 6.7.13 起投资者账户登录支持双因素认证：`ReqGenSMSCode`（BrokerID、UserID、Mobile 必填）→ `OnRspGenSMSCode`，登录请求 `CThostFtdcReqUserLoginField.SMSCode` 填验证码；相关错误 6014～6021、6023（非预留手机号、未开启短信验证、重复申请、验证码不匹配/已使用/已过期、需要填写验证码等）。
- 柜台有“程序化交易频繁报撤单管理”配置，限制每秒报撤单笔数，超限提示“CTP:下单频率限制”（见 §2.9）。
- 交易所对程序化/高频的异常交易监管见 §2.5（计算机程序自动批量下单、快速下单影响交易所系统安全或正常交易秩序属异常交易行为）。程序化/高频报备的具体办理按交易所与期货公司规定（工程建议）。

### 2.7 交易时段与夜盘
- 具体品种的交易节、夜盘品种和时间以交易所公告及合约状态推送（`OnRtnInstrumentStatus`、`ReqQryInstrumentStatus`）为准，不要硬编码（工程建议）。
- 夜盘属于下一个交易日：`TradingDay` 为交易日，`ActionDay` 为实际自然日。示例：2019-08-30（周五）21:00 起的夜盘，TradingDay=20190902（周一），ActionDay=20190830。日盘两者一致。
- 行情中各所夜盘日期字段取值不同（旧版培训资料）：TradingDay——上期所、中金所、大商所夜盘为下一交易日，郑商所夜盘为当日；ActionDay——上期所、中金所夜盘为当日自然日，大商所同交易日，郑商所为当日。跨午夜后自然日会再变化，合成时间戳时需特别处理（工程建议，请在目标环境验证）。
- 下午开盘前没有集合竞价；集合竞价时不更新买卖价/量；集合竞价时发送的市价单会被交易所认为没有对手方，作交易不成功自动撤单。
- FAK/FOK 不得在集合竞价时段使用。
- 上期能源的市价、套利指令，交易所仅允许在合约处于“连续交易”状态时报入；集合竞价报单阶段仅允许撤销“转限价后的市价报单”或套利合约报单，不允许报入市价、套利指令。
- 预埋单只能在非交易时段（集合竞价前或交易节之间的休息时间）报入，并在新交易时段开始时触发。
- 柜台可设置“期权到期日盘后禁止终端行权及做期权自对冲”的时间窗口，窗口内申报返回 6022“CTP:该时间为到期日盘后禁止客户端自对冲时间，禁止申报”。

### 2.8 涨跌停与限仓
- 涨跌停价：`CThostFtdcDepthMarketDataField.UpperLimitPrice/LowerLimitPrice`；上期所市价单保护价须位于涨跌停板之间。
- 持仓限额：由交易所规定，超过会触发强平（`ForceCloseReason=ClientOverPositionLimit('2')`），见《07》§2.8；单笔最大下单手数 `MaxLimitOrderVolume`/`MaxMarketOrderVolume`，查合约获得。
- 自然人客户不得持有进入交割月的合约。

### 2.9 交易所流控
CTP 的流量控制分布在多处：

| 类型 | 含义 | 配置位置 | 触发表现 |
|---|---|---|---|
| 报单流控 | 报单(ReqOrderInsert)、撤单(ReqOrderAction)每秒最大笔数 | CTP 柜台“程序化交易频繁报撤单管理”菜单 | `OnRspOrderAction` 提示“CTP:下单频率限制” |
| 查询流控 | 当前 Session 每秒最大查询请求数；投资者受限，操作员不受限 | 交易前置 `QryFreq`（front_se 组件）；API 内置在途流控 1 笔 | 超前置配置：`OnRspError`“CTP：查询未就绪，请稍后重试”；超在途流控：请求返回值 -2（未处理请求超过许可数） |
| FTD 报文流控 | 当前 Session 每秒最大 API 请求数（登录、查询、报单、撤单、报价等全部算入） | 交易前置 `FTDMaxCommFlux` | 超出的指令缓存在前置、下一秒发出，**无错误返回**，表现为延迟大 |
| 前置连接数流控 | 同一 IP 每秒允许的最大连接请求数（init 到 OnFrontConnected） | 交易前置 `ConnectFreq`（不设置=不限制） | 被主动断开，触发 `OnFrontDisconnected`；白名单：front_se 的 bin 目录下建文件 `whiteiplist`，每行一个 IP |
| 同一用户最大在线会话数 | 同一 UserID 在整个交易系统同时在线会话上限（非单一前置） | 柜台或交易核心；后台 6.6.3 起可按用户设置 | `OnRspUserLogin` 返回“CTP:用户在线会话超出上限” |
| 交易所 API 流控 | 通过交易所 API 发送请求的每秒上限，阈值在交易所端 | 交易所 | `OnRtnOrder` 报“CTP：交易所每秒发送请求数超过许可数”或“CTP:交易所未处理请求超过许可数” |

补充：
- 穿透式监管版本之后，API 连接前置时会查询前置的查询流控设置（例如前置配 2 笔/秒，则 API 每秒只能发 2 笔查询）；旧版查询流控内置在 API，1 笔/秒、在途 1 笔。
- 在途查询流控：当前查询未收完全部响应前不能发起下一笔查询。
- 以 ReqQuery 开头的查询函数不受流控限制（经交易核心处理，不经查询核心）。
- 行情流控见 API 页面“行情流控”。
- （工程建议）发送端做令牌桶限速；查询串行化；以 `OnRspError`/返回值 -2 作退避信号。

## 3. 标准流程/时序

### 3.1 FAK 部分成交（上期所组）
```
ReqOrderInsert → OnRtnOrder('a'未知) → OnRtnOrder('5'撤单, VolumeTraded>0) → OnRtnOrder('5')+OnRtnTrade (每笔成交)
```
### 3.2 FAK 部分成交（大商所组）
```
ReqOrderInsert → OnRtnOrder('a') → OnRtnOrder('3') → [OnRtnOrder('1') + OnRtnTrade]* → OnRtnOrder('5')
```
### 3.3 FAK 部分成交（郑商所）
```
ReqOrderInsert → OnRtnOrder('a') → OnRtnOrder('3') → [OnRtnOrder('3') + OnRtnOrder('1') + OnRtnTrade]* → OnRtnOrder('5')
```

## 4. 代码范例

```cpp
// 通用: 构造 FAK（限价，立即成交剩余撤销）
CThostFtdcInputOrderField o{};
// ... BrokerID/InvestorID/InstrumentID/OrderRef/Direction/Volume/Price 略
o.OrderPriceType     = THOST_FTDC_OPT_LimitPrice;     // '2'
o.TimeCondition      = THOST_FTDC_TC_IOC;             // '1'
o.VolumeCondition    = THOST_FTDC_VC_AV;              // '1'  (上期所/中金所也可用 MV + MinVolume)
o.MinVolume          = 1;
o.ContingentCondition= THOST_FTDC_CC_Immediately;     // '1'
o.ForceCloseReason   = THOST_FTDC_FCC_NotForceClose;  // '0'

// FOK
o.VolumeCondition = THOST_FTDC_VC_CV;                 // '3'
o.MinVolume       = o.VolumeTotalOriginal;

// 上期所市价单(保护价)
o.OrderPriceType  = THOST_FTDC_OPT_AnyPrice;          // '1'
o.TimeCondition   = THOST_FTDC_TC_IOC;
o.VolumeCondition = THOST_FTDC_VC_CV;                 // 市价 FOK; AV=市价 FAK
o.LimitPrice      = protectPrice;                     // 须在涨跌停之间

// 大商所止损单
o.ContingentCondition = THOST_FTDC_CC_LastPriceLesserThanStopPrice; // 止损/止盈类，StopPrice 填触发价
o.TimeCondition       = THOST_FTDC_TC_GFD;

// 中金所五档价
o.OrderPriceType = THOST_FTDC_OPT_FiveLevelPrice;     // 'G'
```

## 5. 常见坑与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 郑商所/大商所 FAK 设了 MinVolume 但无效 | MV 不生效 | 用 AV；自行控制数量 |
| FAK 收到撤单后又收到成交 | 上期所组撤单行先于成交行 | 以 OnRtnTrade 为成交真值，不凭终态丢弃后续回报 |
| 按 '1' 状态累加成交量漏算 | 上期所 FAK 无 '1' | 用 OnRtnTrade |
| 郑商所成交重复计数 | 前态+新态各一条 | 去重 / 用 OnRtnTrade |
| 组合市价单被拒 | 不支持 | 限价 |
| 上期所平仓被当作平昨 | 报 Close 视为平昨 | 明确 CloseToday/CloseYesterday |
| 大商所放弃行权被拒 | 不支持放弃 | 取消到期自动行权（Volume=0）后行权剩余手数（见《07》） |
| 被通知异常交易 | 自成交≥5、撤单≥500 等 | 控制撤单频率，用 FAK/FOK/套利/套保编码，避免自成交 |
| 集合竞价报 FAK/FOK 被拒 | 不得在集合竞价使用 | 连续竞价后使用 |
| 报价/报单被流控 | 超过频率 | 限速 |

## 6. 检查清单
**Do**：按交易所选择 FAK 字段组合；上期所市价单设保护价；监控自成交/撤单次数；FAK 以 OnRtnTrade 为成交真值；记录 ActionDay/TradingDay。
**Don't**：不要统一假设各所回报形状；不要集合竞价使用 FAK/FOK；不要对组合合约发市价；不要在大商所/郑商所依赖 MV。
