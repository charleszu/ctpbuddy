   - **前置每秒查询笔数（配置项 QryFreq，配置在交易前置 front_se 组件）**：穿透式监管版本起，API 连接前置时读取该配置（如前置配 2 笔/秒，则该 API 每秒只能发 2 笔查询）；旧版 API 内置固定“每秒 1 笔、在途 1 笔”。超过时触发 `OnRspError`，提示“CTP：查询未就绪，请稍后重试”（ErrorID 90），该查询不执行；旧版 API 超每秒笔数时请求函数返回 -3；
   - 请求函数返回值：`0` 成功发出；`-1` 网络连接失败；`-2` 未处理请求超过许可数；`-3` 每秒发送请求数超过许可数；流控对象是当前 Session 的投资者，操作员不受流控限制；
   - 其它流控：报单流控（柜台“程序化交易频繁报撤单管理”配置每秒最大报/撤单笔数，超限 `OnRspOrderAction` 提示“CTP:下单频率限制”）；FTD 报文流控（FTDMaxCommFlux，登录/查询/报单/撤单等所有请求合计，超限指令缓存在前置到下一秒发出，**无任何错误提示**，表现为延迟）；前置连接数流控（ConnectFreq，超限被主动断开触发 OnFrontDisconnected）；同用户最大在线会话数（超限 `OnRspUserLogin` 返回“CTP:用户在线会话超出上限”）；交易所 API 流控（`OnRtnOrder` 报“CTP：交易所每秒发送请求数超过许可数”或“未处理请求超过许可数”）。详见流控相关章节。

## 1. 要点速查表

| 主题 | 请求 / 回调 | 关键点 |
|---|---|---|
| 持仓汇总 | `ReqQryInvestorPosition` / `OnRspQryInvestorPosition` | 按 合约+方向+(持仓日期) 汇总；当日被全平的记录仍返回，Position=0；结算后清除 |
| 持仓明细 | `ReqQryInvestorPositionDetail` / `OnRspQryInvestorPositionDetail` | 开仓成交产生的逐笔持仓；Volume=0 的当日全平明细仍返回 |
| 资金 | `ReqQryTradingAccount` / `OnRspQryTradingAccount` | 结果为单条；字段含 PreBalance/Balance/Available/CurrMargin 等 |
| 保证金率 | `ReqQryInstrumentMarginRate` | 投资者实际保证金率；必须填 HedgeFlag |
| 手续费率 | `ReqQryInstrumentCommissionRate` | 按品种(或合约)返回；开/平/平今 的 按金额与按手数 |
| 报单手续费率 | `ReqQryInstrumentOrderCommRate` | 报单/撤单手续费（申报费），部分交易所收取 |
| 合约 | `ReqQryInstrument` | 合约属性：乘数、最小变动价位、持仓日期类型、到期日、期权信息等 |
| 结算单 | `ReqQrySettlementInfo` / `ReqSettlementInfoConfirm` | 文本分多段返回，需拼接；必须确认后才能报单（视期货公司配置） |
| 报单/成交 | `ReqQryOrder` / `ReqQryTrade` | 当日全部，仅当日；用于启动时恢复 |
| 查询流控 | — | 同时仅1笔在途查询，约1秒1次（可能由柜台配置）；超限返回 ErrorID=-2/-3（请求返回值）|
| 空结果 | — | 无数据仍会回调一次：数据指针为空、bIsLast=true |

核心公式（逐日盯市）：

```
静态权益 = PreBalance + Deposit - Withdraw
动态权益(Balance) = 静态权益 + PositionProfit + CloseProfit + CashIn - Commission
可用资金(Available) = 由 `ReqQryBrokerTradingParams` 返回的 `Algorithm`、`AvailIncludeCloseProfit`、`MarginPriceType` 等柜台参数决定；此处常见公式仅作某一环境的示例，不作为普遍恒等式。
多头持仓盈亏 = (最新价 - 持仓均价) × 合约乘数 × 持仓数量
空头持仓盈亏 = (持仓均价 - 最新价) × 合约乘数 × 持仓数量
可平数量(多头持仓) = Position - ShortFrozen - CombShortFrozen
可平数量(空头持仓) = Position - LongFrozen  - CombLongFrozen
当前昨仓 = Position - TodayPosition
开仓均价 = OpenCost / (Position × 乘数)；持仓均价 = PositionCost / (Position × 乘数)
```

## 2. 详细说明

### 2.1 查询通用规则

1. **回调模型**：每个 `ReqQryXxx` 对应 `OnRspQryXxx(数据指针, pRspInfo, nRequestID, bIsLast)`。多条记录分多次回调，最后一条 `bIsLast == true`。
2. **空结果也有回调**：没有符合条件的数据时，仅回调一次，数据指针为 `nullptr`，`bIsLast == true`。因此必须先判空指针再解引用，且不能只在“收到数据”时才结束等待。
3. **出错回调**：查询失败时 `pRspInfo->ErrorID != 0`，数据指针通常为空，`bIsLast == true`。
4. **nRequestID 对应**：回调里的 `nRequestID` 与请求时传入的一致，用于将响应匹配到请求；应使用递增且唯一的请求号，并建立 请求号 → 查询类型/promise 的映射。（工程建议）
5. **拼包**：同一个 nRequestID 的多次回调要累积到缓冲，`bIsLast` 时才视为完整；不要在中间回调中判断“没有某合约=无持仓”。
6. **查询流控**：
   - **API 内置在途流控：同一时刻仅允许 1 笔在途查询**，上一笔未收完全部响应（`bIsLast=true`）前不能发下一笔，否则请求函数**返回 -2**（未处理请求超过许可数），请求不会发出；此限制与前置配置无关，永远存在。
   - **前置每秒查询笔数（配置项 QryFreq，配置在交易前置 front_se 组件）**：穿透式监管版本起，API 连接前置时读取该配置（例如前置配 2 笔/秒，则该 API 每秒只能发 2 笔查询）；旧版 API 内置固定“每秒 1 笔、在途 1 笔”。超过时触发 `OnRspError`，提示“CTP：查询未就绪，请稍后重试”（ErrorID 90），该查询不执行；旧版 API 超每秒笔数时请求函数返回 -3。
   - 请求函数返值：`0` 成功发出；`-1` 网络连接失败；`-2` 未处理请求超过许可数；`-3` 每秒发送请求数超过许可数。流控对象是当前 Session 的投资者，操作员不受流控限制。
   - 其它流控：报单流控（柜台“程序化交易频繁报撤单管理”配置每秒最大报/撤单笔数，超限 `OnRspOrderAction` 提示“CTP:下单频率限制”）；FTD 报文流控（FTDMaxCommFlux，登录/查询/报单/撤单等所有请求合计，超限的指令缓存在前置到下一秒发出，**无任何错误提示**，表现为延迟）；前置连接数流控（ConnectFreq，超限被主动断开触发 OnFrontDisconnected）；同用户最大在线会话数（超限 `OnRspUserLogin` 返回“CTP:用户在线会话超出上限”）；交易所 API 流控（`OnRtnOrder` 报“CTP：交易所每秒发送请求数超过许可数”或“未处理请求超过许可数”）。
   - **-2 与 90 的处理不同**：-2 是在途未完成，应等上一笔 `bIsLast` 后再发，sleep 无效；在 SPI 回调线程里 sleep 会阻塞 API 底层的 socket 读写（二者同线程），响应反而更晚到；90/-3 是超频，等待 ≥1 秒后重试有效。
   - 推荐：建立查询队列，每个 SPI 回调里只放一个查询并串行等待响应；以 `bIsLast` 作为“释放”信号；对 90/-3 做 ≥1.1 秒退避重试。（工程建议）
   - 另有资料称 `ReqQuery*` 开头的函数不受查询流控限制（经交易核心处理，不经查询核心）。
7. **BrokerID / InvestorID 可留空**：留空表示查询当前登录账户；`InstrumentID`、`ExchangeID` 留空表示不限制。
8. **查询只含当日交易日信息**：查询不返回历史成交/报单（历史对账用结算单）。
9. 查询结果本质是**柜台时点快照**，与实时回报（OnRtnOrder/OnRtnTrade）之间存在竞态，见 2.3 与第 5 章。

### 2.2 持仓汇总与持仓明细

#### 2.2.1 持仓汇总 ReqQryInvestorPosition

查询条件结构 `CThostFtdcQryInvestorPositionField`：BrokerID、InvestorID、InstrumentID（可空）、ExchangeID（可空）、InvestorUnitID（6.x 新增，可选）。

**持仓 key**：`BrokerID + InvestorID + HedgeFlag + PosiDirection + PositionDate`（实际单账户可简化为 InstrumentID + PosiDirection + PositionDate [+ HedgeFlag]；合约代码当然要作为 key 的一部分）。

**今仓/昨仓区分**：
- 上期所(SHFE)、能源中心(INE)区分今仓与昨仓：同一合约同一方向返回**最多 2 条**（`PositionDate = THOST_FTDC_PSD_Today('1')` 今仓 与 `THOST_FTDC_PSD_History('2')` 历史仓）。
- 其他交易所（大商所 DCE、郑商所 CZCE、中金所 CFFEX、广期所 GFEX 等）不区分，只有一条，PositionDate 通常为今仓，意义不大。
- 是否区分可从合约/产品属性中的 `PositionDateType`（`THOST_FTDC_PDT_UseHistory '1'` 区分今昨 / `THOST_FTDC_PDT_NoUseHistory '2'` 不区分）判断。
- 例：上期所 rb2010 多今1、多昨2、空今3、空昨4 → 返回 4 条；大商所 c2105 同样持仓 → 返回 2 条（多3、空7）。

**持仓汇总字段说明**（完整字段见《16_结构体字段速查表》）：

| 字段 | 含义 |
|---|---|
| PosiDirection | 持仓多空方向：净 `'1'`、多头 `'2'`、空头 `'3'` |
| HedgeFlag | 投机 '1' / 套利 '2' / 套保 '3' / 做市商 '5' |
| PositionDate | 持仓日期类型：今仓 '1' / 历史仓 '2' |
| YdPosition | 上日持仓（昨日收盘时的持仓数量），**静态**，日内不随开平仓变化；≠当前昨仓 |
| Position | 当前总持仓数量（含今仓） |
| TodayPosition | 今日新开仓数量（今仓） |
| LongFrozen / ShortFrozen | 多头/空头冻结：未成交的买入/卖出委托（含开仓和平仓）的未成交数量；统计口径随委托的冻结而变化 |
| LongFrozenAmount / ShortFrozenAmount | 开仓冻结金额 |
| OpenVolume / CloseVolume | 当日开仓量 / 当日平仓量 |
| OpenAmount / CloseAmount | 当日开仓成交额 / 平仓成交额 |
| PositionCost | 持仓成本 = Σ明细（持仓价×数量×乘数）；昨仓以昨结算价为持仓价，今仓以开仓价 |
| OpenCost | 开仓成本 = Σ明细（开仓价×数量×乘数） |
| PreMargin | 上次占用的保证金 |
| UseMargin | 占用的保证金 |
| FrozenMargin | 冻结的保证金（开仓未成交委托） |
| FrozenCash | 冻结的资金（期权买入权利金） |
| FrozenCommission | 挂单预估冻结的手续费，盘中也可能非 0 |
| CashIn | 资金差额（期权权利金收支） |
| Commission | 当日该持仓上产生的手续费（成交记录里没有手续费，手续费体现在持仓中） |
| CloseProfit | 平仓盈亏（逐日盯市口径）|
| PositionProfit | 持仓盈亏（逐日盯市口径，期权为0）|
| PreSettlementPrice / SettlementPrice | 上次结算价 / 本次结算价 |
| TradingDay | 交易日 |
| SettlementID | 结算编号 |
| ExchangeMargin | 交易所保证金 |
| CombPosition / CombLongFrozen / CombShortFrozen | 组合持仓 / 组合多头冻结 / 组合空头冻结 |
| CloseProfitByDate | 逐日平仓盈亏（按昨结算价计的当日平仓盈亏）|
| CloseProfitByTrade | 逐笔平仓盈亏（按开仓价计）|
| MarginRateByMoney / MarginRateByVolume | 保证金率 / 保证金率(按手数) |
| StrikeFrozen / StrikeFrozenAmount / AbandonFrozen | 期权执行冻结、放弃执行冻结 |
| YdStrikeFrozen | 个股期权用，期货期权为0 |
| PositionCostOffset | 大商所持仓成本差值 |
| TasPosition / TasPositionCost | 套利（TAS）持仓 |

**重要语义**：
- 持仓中带“统计”性质的字段（Commission、CloseProfit、OpenAmount、LongFrozen…）表示该持仓记录上当日所有对应事件的累计。例如 CF101 多头 4 手平 1 手，平仓盈亏计入剩下 3 手的多头持仓记录。
- 持仓里**没有**：当前昨仓数量、开仓均价、持仓均价、可平数量；需要自己算（见速查表）。
- 当日已全部平仓的持仓仍出现在查询里（Position=0，但 CloseProfit、Commission 有值）；结算后清除。
- 开仓委托未成交且此前无该合约持仓：也会产生一条 Position=0 的记录，其中 FrozenMargin 等有数据。
- 期权（期货期权）没有持仓盈亏与平仓盈亏，为 0。

#### 2.2.2 持仓明细 ReqQryInvestorPositionDetail

查询条件 `CThostFtdcQryInvestorPositionDetailField`：BrokerID、InvestorID、InstrumentID、ExchangeID、InvestorUnitID。

**明细 key**：`BrokerID + InvestorID + HedgeFlag + Direction + OpenDate + TradeID + TradeType`。
单账户、无套保/组合交易时简化为 `OpenDate + TradeID`（保险起见加上 Direction 与 InstrumentID）。**不同交易日的 TradeID 可能重复**，所以 OpenDate 必须参与 key。

**明细字段**（完整见《16_结构体字段速查表》）：

| 字段 | 含义 |
|---|---|
| InstrumentID / ExchangeID | 合约、交易所 |
| HedgeFlag / Direction | 投机套保标志 / 买卖方向（开仓成交的方向，'0'买即多头明细） |
| OpenDate | 开仓日期（交易日） |
| TradeID | 开仓成交编号 |
| Volume | 当前剩余数量（平仓后减少，减到0仍当日可见） |
| OpenPrice | 开仓价 |
| TradingDay / SettlementID | 交易日 / 结算编号 |
| TradeType | 成交类型：普通 '0'、期权执行 '1'、OTC '2'、期转现衍生 '3'、组合衍生 '4'、BlockTrade '5' |
| CombInstrumentID | 组合合约代码（组合成交产生的明细） |
| CloseProfitByDate | 逐日盯市平仓盈亏 |
| CloseProfitByTrade | 逐笔对冲平仓盈亏 |
| PositionProfitByDate | 逐日盯市持仓盈亏 |
| PositionProfitByTrade | 逐笔对冲持仓盈亏 |
| Margin | 投资者保证金 |
| ExchMargin | 交易所保证金 |
| MarginRateByMoney / MarginRateByVolume | 保证金率 / 按手数 |
| LastSettlementPrice | 昨结算价 |
| SettlementPrice | 结算价 |
| CloseVolume / CloseAmount | 平仓量 / 平仓金额 |
| TimeFirstVolume | 先开先平的剩余数量（6.x，用于上期所今仓内平仓排序）|
| SpecPosiDetailType 等 | 特殊持仓明细标识（TAS 等） |

**明细语义**：
- 平仓使 Volume 减少；Volume=0 的当日全平明细仍然返回；结算后清除。CloseVolume 记录该明细当日累计被平数量。
- 昨仓明细的 OpenDate < 今日交易日；昨仓在日结后其“持仓价”变为昨结算价（盯市后），但 OpenPrice 保持原开仓价（逐笔对冲口径用）。
- 查询明细同一天内返回顺序**不保证**为开仓顺序，也不含开仓时间（如本地保存了成交数据，建议把成交时间补进本地明细，用于确定平仓顺序）。（工程建议）
- 明细汇总可合成持仓汇总（见 2.3.5）。
- 返回条数多时耗时长，同样受流控。

### 2.3 持仓本地维护算法

目标：用 OnRtnOrder / OnRtnTrade / OnRspOrderInsert / OnErrRtnOrderInsert / 行情 实时维护持仓（汇总+明细）与资金，只在启动（和必要的对账）时查询。以下是通用的盯市口径规则（推测 CTP 柜台内部类似），最终以柜台查询结果为准。

#### 2.3.1 数据模型
- 持仓汇总 `Position[合约, 持仓方向, (日期类型)]`，持仓明细 `Detail[OpenDate, TradeID, ...]`。
- 资金字段大多是持仓字段的汇总：`CloseProfit = Σ持仓平仓盈亏`，`PositionProfit = Σ持仓持仓盈亏`，`CashIn = Σ`，`Commission = Σ`，`CurrMargin = Σ UseMargin`，`FrozenMargin = Σ`，`FrozenCommission = Σ`，`FrozenCash = Σ`。
- 这些求和字段均为**当日**数据，结算后清零。

#### 2.3.2 收到行情时
更新该合约持仓的持仓盈亏，再更新账户动态权益：
```
多头持仓盈亏 = (最新价 - 持仓均价) × 乘数 × 持仓数量
空头持仓盈亏 = (持仓均价 - 最新价) × 乘数 × 持仓数量
```
持仓均价昨仓用昨结算价，今仓用开仓价（见 2.3.5）。

#### 2.3.3 报单时（本端发出 ReqOrderInsert）
立即在本地更新，不要等待 OnRtnOrder（回报有延迟，期间持仓数据不准，可能导致重复平仓）。

- **开仓报单**：冻结保证金、冻结手续费；买开 → 多头持仓 LongFrozen += 报单量；卖开 → 空头持仓 ShortFrozen += 报单量。
  ```
  增加的冻结保证金 = 昨结算价 × 乘数 × 保证金率 × 报单数量 + 保证金(按手数) × 报单数量
  ```
  （冻结价格口径因期货公司而异，由 `ReqQryBrokerTradingParams` 的 MarginPriceType 决定：昨结算价'1'/最新价'2'/成本价'3'/开仓价'4'。冻结手续费计算复杂且金额小，可忽略。目前国内期货按手数的保证金暂为 0；多空保证金率目前相等，但存在未来多空独立设置的可能。）
  期权买入开仓：多头无保证金，无冻结保证金，但需冻结权利金：`冻结权利金 = 报单数量 × 价格(参考昨结算价) × 合约乘数`。
- **平仓报单**：冻结持仓：买平 → 空头持仓的 LongFrozen += 报单量；卖平 → 多头持仓的 ShortFrozen += 报单量。
  ```
  可平数量(多头) = Position - ShortFrozen - CombShortFrozen
  可平数量(空头) = Position - LongFrozen  - CombLongFrozen
  ```
  区分今昨的交易所需分别对应今仓/昨仓记录冻结（平今 → 今仓；平仓/平昨 → 昨仓）。

#### 2.3.4 报单失败与撤单
- **OnRspOrderInsert 带错误**（或 OnErrRtnOrderInsert）：撤销上面的冻结，数量=报单数量。
- **OnRtnOrder**：仅当状态为已撤单(`OrderStatus == THOST_FTDC_OST_Canceled '5'`)时更新：解冻量 = 剩余数量 `VolumeTotal`（未成交部分），无论主动撤单还是被动（如 FAK/FOK、交易所拒绝）。非终态不更新持仓/资金。
- **多端登录**：OnRtnOrder 会推给同一账户登录的所有终端。非本端报单没有做过“报单时冻结”，若直接解冻会出错。方案：①多程序间同步；②按 `FrontID + SessionID`（及 OrderRef）判断是否本端报单，若非本端且是首次收到该报单通知，补做报单时的冻结。

#### 2.3.5 成交时（OnRtnTrade）
**开仓成交**：
1. 新增一条持仓明细：OpenDate=成交 TradingDay；TradeID/TradeType/Direction/HedgeFlag 同成交；OpenPrice=成交价；Volume=成交量；持仓价=开仓价；
   `Margin = Volume × Price × 乘数 × 保证金率 + Volume × 保证金(按手数)`。
2. 修改持仓汇总：Position、OpenVolume、TodayPosition += 成交量；UseMargin += 明细 Margin；LongFrozen（多）/ShortFrozen（空） -= 成交量；冻结保证金按成交量解冻；
   `PositionCost += Volume × Price × 乘数`，`OpenCost += 同`；
   `持仓均价 = PositionCost / (Position × 乘数)`，`开仓均价 = OpenCost / (Position × 乘数)`；
   `Commission += 成交价 × 成交量 × 乘数 × 开仓手续费率 + 成交量 × 开仓手续费(按手数)`。

**平仓成交**：
1. 先确定各笔持仓明细被平的数量（平仓顺序规则）：
   - 不区分今昨的交易所（如大商所）：先开先平，即先平昨仓再平今仓；
   - 区分今昨的交易所（上期所、能源中心）：按成交的开平标志（平今 `'3'` / 平仓/平昨 `'1'`、`'4'`）确定今仓或昨仓明细。
2. 对每笔被平明细（平仓数量 N）：
   - Volume -= N；重算该明细保证金；CloseVolume += N；
   - 平仓盈亏增量：多头明细 `(成交价 - 持仓价) × N × 乘数`；空头明细 `(持仓价 - 成交价) × N × 乘数`；
   - 持仓价：历史明细（OpenDate ≠ 今日）= **昨结算价**；今日明细 = **开仓价**；
   - 该明细手续费 = `成交价 × N × 乘数 × 平仓手续费率 + N × 平仓手续费(按手数)`。**即使大商所等不区分今昨，手续费率仍区分平今/平昨**，必须按实际平今/平昨取费率，不能统一用平昨费率。
3. 本笔成交的平仓盈亏、手续费 = 各明细之和。
4. 用明细重新汇总持仓：
   ```
   Position = Σ明细 Volume
   UseMargin = Σ明细 Margin
   CloseVolume = Σ明细 CloseVolume
   CloseProfit = Σ明细 CloseProfit
   TodayPosition = Σ(OpenDate == 今日 的明细 Volume)
   OpenCost = Σ(OpenPrice × Volume × 乘数)
   PositionCost = Σ(持仓价 × Volume × 乘数)
   Commission += 本笔手续费
   ```
5. 空头冻结（多头持仓）/ 多头冻结（空头持仓）-= 成交量。
6. 期权卖出成交（开或平）另有权利金收入，CashIn 增加 = 成交量×成交价×乘数；买入成交则 CashIn 减少，冻结权利金解冻。

**平仓例**：4 手 c2101 多头：昨仓 2 手（开仓价 3006）、今仓 2 手（3000）；昨结算价 3005，乘数 10，多头保证金率 5%，平昨手续费 1.2 元/手，平今免手续费；卖平 3 手，成交价 3004。顺序：2 手昨仓 + 1 手今仓。
- 昨仓明细平仓盈亏 = (3004-3005)×10×2 = -20；手续费 2×1.2 = 2.4
- 今仓明细平仓盈亏 = (3004-3000)×10×1 = 40；手续费 0
- 本笔成交平仓盈亏 = 20，手续费 = 2.4
- 剩余：1 手今仓，开仓/持仓成本 30000，均价 3000，保证金 1500；CloseVolume 增加 3，CloseProfit 增加 20，Commission 增加 2.4。

#### 2.3.6 与查询结果的对账
- 启动时：先查持仓明细与持仓汇总（及资金）作为初始状态，再开始处理回报；必须处理“查询过程中到达的回报”与“查询快照”重叠的问题（见 5.x）。（工程建议）
- 日结后（新交易日登录）：昨日 Position 变为今日 YdPosition，今仓转昨仓（上期所今仓 → 历史仓），持仓价改为昨结算价，当日累计字段清零。

#### 2.3.7 持仓字段在不同阶段的变化示例（单合约多头）
| 事件 | 持仓字段变化 |
|---|---|
| 首次买开 1 手报单（未成交） | 新建一条持仓记录（Position=0）；LongFrozen+1；LongFrozenAmount += 报单价×手数×乘数；FrozenMargin += (价格×乘数×保证金率(按金额)+保证金(按手数))×手数；FrozenCommission 类似 |
| 买开成交 | LongFrozen-1、冻结金额/冻结保证金/冻结手续费解冻；Position+1、TodayPosition+1、OpenVolume+1、OpenAmount+成交额；UseMargin、OpenCost、PositionCost 增加；Commission 增加 |
| 买开未成交后撤单 | 冻结字段全部回到报单前状态；持仓记录仍保留（Position=0） |
| 昨仓 1 手，卖平报单 | ShortFrozen+1（在多头持仓记录上）；YdPosition=Position=1 不变；可平数量=Position-ShortFrozen=0 |
| 卖平成交（全平） | Position 回到 0；YdPosition 仍为 1（静态）；CloseVolume+1；CloseProfit、Commission 累计；PositionCost/OpenCost/UseMargin 清零；记录仍保留至结算 |

> 平仓冻结未解除前再次报平仓，柜台会拒绝，错误信息如“CTP:平仓量超过持仓量”。故可平数量必须在**报单时**即刻扣减。

#### 2.3.8 组合持仓对汇总的影响
部分交易所在盘后（或盘中申请）将满足规则的两腿持仓自动组合，组合后只收较大一边保证金。此时持仓查询除了单腿合约记录外，还会多出组合合约（如 SPD、SP、IPS、CSPD 类组合合约代码）的持仓记录，且单腿记录里的 `CombPosition`、`CombLongFrozen`、`CombShortFrozen` 有值。可平数量计算必须扣减 CombXxxFrozen（见速查）。详见《07_期权与组合合约》及 2.5.7。

**组合合约持仓记录规则**：
1. **开仓**：持仓查询生成 3 条记录：组合合约记录 + 两条分腿记录。近期腿的多空方向与组合合约一致，远期腿与组合合约相反。
2. **组合合约记录**只计算：上日持仓、今日持仓、总持仓、开仓量、保证金；其平仓量、平仓盈亏、持仓成本、持仓盈亏、手续费都记在分腿记录中。
3. **分腿记录**的上日持仓、今日持仓、总持仓、开仓量、平仓量是“单一合约持仓 + 组合形成持仓”的总和，要区分必须查持仓明细；分腿的**保证金字段只含单一持仓部分**，组合部分保证金存放在组合合约记录里；但开仓成本、开仓均价、持仓成本、持仓均价、持仓盈亏、平仓金额、平仓盈亏、手续费涵盖所有持仓（含组合形成的）。
4. **平仓顺序：先单一后组合，先开先平**。先平该合约的单一头寸（按先开先平），不足再平组合头寸（同样先开先平）。用到组合头寸时发生“打散”：自身分腿的组合持仓减少、平仓量增加；组合合约记录持仓量减少；另一条分腿的组合持仓减少，并衍生出一笔单一持仓（数量等于被打散部分，撮合编号与开仓时间与原组合一致）。
5. **组合冻结**：多头开仓冻结 → 组合合约记录的多头冻结增加，近期腿的组合多头冻结增加，远期腿的组合空头冻结增加；多头平仓冻结 → 组合合约记录的空头冻结增加（可平数量减少），近期腿的组合空头冻结增加，远期腿的组合多头冻结增加。

**打散示例**（A、B 为分腿，AB、BC 为组合）：

| 场景 | 初始 | 操作 | 结果 |
|---|---|---|---|
| 单一平仓用到一笔组合头寸 | A单4、AB组合2；B单3、AB组合2 | 平 A 5 手 | A单0、AB组合1；B单4（衍生1手）、AB组合1；AB共1手 |
| 单一平仓用到多个组合 | A单0、AB 1；B单3、AB 1、BC 7（AB先开）；C单0、BC 7 | 平 B 5 手 | 先平B单3，再打散AB 1手、再打散BC 1手：A单1；B单0、AB 0、BC组合6；C单1、BC 6 |
| 组合平仓只用自身头寸 | A单0、AB组合4；B单1、AB组合4（组合先开） | 平 AB 3 手 | A腿成交时打散3手组合；B腿衍生3手单一（开仓时间早于原有1手）故先平衍生的3手；结果 A单0、AB组合1；B单1(原有)、AB组合1 |
| 组合平仓用到其他组合 | A单1、AB 2；B单0、AB 2、BC 3（BC先开）；C单1、BC 3 | 平 AB 1 手 | A用单一；B打散BC 1手；结果 A单0、AB 2；B单0、AB 2、BC 2；C单2（衍生1手）、BC 2 |
| 组合平仓用单一头寸 | A单2、AB 0；B单1、AB 0 | 平 AB 1 手 | AB无持仓但两分腿都有持仓即可平：A单1，B单0 |
| 混合 | A单0、AB 2；B单0、AB 2、BC 2（AB先开）；C单2、BC 2 | 平 BC 3 手 | B腿先打散AB 2手（A衍生2手单一），再打散BC 1手（C衍生1手单一）；C腿单一3手全平；结果 A单2；B全0、BC组合1；C单0、BC 1 |

#### 2.4.1 资金公式（逐日盯市）
```
静态权益            = PreBalance + Deposit - Withdraw       （6.x 另含 PreCredit/质押等，视期货公司）
动态权益(Balance)   = 静态权益 + PositionProfit + CloseProfit + CashIn - Commission
可用资金(Available) = 由 `ReqQryBrokerTradingParams` 返回的 `Algorithm`、`AvailIncludeCloseProfit`、`MarginPriceType` 等柜台参数决定；此处常见公式仅作某一环境的示例，不作为普遍恒等式。
风险度              = (CurrMargin [+ FrozenMargin]) / Balance × 100%   （期货公司口径，多数以占用保证金为分子）
可取资金(WithdrawQuota) ≈ 受 Reserve/Available/风控限制，取实际查询值
```
说明：
- 最后一行：风险度公式不同期货公司可能不同；常见为 `CurrMargin / Balance`；若含冻结保证金则加上 FrozenMargin。（工程建议）
- 以上求和型字段由持仓汇总：`PositionProfit=Σ持仓盈亏`，`CloseProfit=Σ持仓平仓盈亏`，`CashIn=Σ`，`Commission=Σ`，`CurrMargin=ΣUseMargin`，`FrozenMargin=Σ`，`FrozenCommission=Σ`，`FrozenCash=Σ`，均为当日量，结算后清零。
- 注意：CTP 资金里的 Balance 是动态权益，没有单独的“权益”字段；Available 可能因期货公司风控参数不同与手算略有差异。
- 入金/出金、银期转账会即时改变 Deposit/Withdraw（有些期货公司次日才计入）。
- **逐日盯市口径下 PositionProfit** 按“最新价（上期所/能源等使用结算价）与昨结算价或今开仓价之差”计算，期权无持仓盈亏。
- 平仓盈亏 CloseProfit：昨仓按昨结算价、今仓按开仓价计算；逐笔口径见 2.8。

#### 2.4.2 资金本地维护
| 触发 | 本地资金更新 |
|---|---|
| 行情（最新价） | 重算相关持仓 PositionProfit → 汇总 → Balance、Available |
| 开仓报单 | FrozenMargin += 估算冻结保证金，FrozenCommission += 估算（可忽略）；Available 减少；期权买开：FrozenCash += 权利金 |
| 报单错误/撤单 | 对应冻结还原 |
| 开仓成交 | 冻结解冻；CurrMargin += 明细 Margin；Commission += 手续费；期权：CashIn ∓ 权利金 |
| 平仓成交 | CurrMargin -= 被平明细保证金；CloseProfit += 本笔；Commission += 本笔；Available 随之增加 |
| 出入金 | Deposit / Withdraw 变化，可通过 OnRtnTradingNotice 或再次查询得知（工程建议：入出金后主动查一次资金） |
| 日结 | PreBalance = 昨日 Balance；当日量全部清零 |

由于 CTP 内部冻结价口径、手续费、保证金优惠（见 2.5）难以完全复刻，本地估算的 Available 与柜台可能有细微差别；以定时（受流控）`ReqQryTradingAccount` 结果校正。（工程建议）

查询资金与回报的竞态：查到的资金是查询处理时刻快照，之后到达的 OnRtnTrade 可能已在快照之内（重复计算）或之外；资金校正宜在无在途委托时做，或直接以查询值覆盖。（工程建议）

### 2.5 保证金率、手续费率与合约属性

#### 2.5.1 与保证金率相关的 4 个查询：该用哪个
| 查询 | 返回内容 | 用途 |
|---|---|---|
| `ReqQryInstrumentMarginRate` | **投资者**对该合约的保证金率（期货公司在交易所基础上加成后的实际值） | **实际冻结/占用保证金的依据** |
| `ReqQryInstrument` | 合约信息中含 LongMarginRatio/ShortMarginRatio，通常是交易所保证金率 | 仅作参考，不用于账户保证金计算（某些期货公司返回值可能已含加成，以 ReqQryInstrumentMarginRate 为准） |
| `ReqQryExchangeMarginRate` | 交易所保证金率（含 LongMarginRatioByMoney/ByVolume/Short...） | 计算中间量 |
| `ReqQryExchangeMarginRateAdjust` | 交易所调整保证金率（如节假日/单边市调整） | 计算中间量 |

另有 `ReqQryInvestorProductGroupMargin`（品种组保证金，大边保证金）、`ReqQryProductGroup`、`ReqQryBrokerTradingParams`（保证金价格类型、算法）、`ReqQryInvestorProdRuleMargin`/`ReqQryInvestorProdSPBMMargin`（风险规则/SPBM 组合保证金，部分柜台）。

##### ReqQryInstrumentMarginRate
- 请求 `CThostFtdcQryInstrumentMarginRateField`：**BrokerID、InvestorID、HedgeFlag 必填**（不填返回空）；InstrumentID 可选——**留空时返回当前持仓合约的保证金率，不会返回所有合约**；要全部只能逐合约查询（受流控，1秒1次）。
- 响应 `CThostFtdcInstrumentMarginRateField`：InstrumentID、InvestorRange、BrokerID、InvestorID、HedgeFlag、`LongMarginRatioByMoney`、`LongMarginRatioByVolume`、`ShortMarginRatioByMoney`、`ShortMarginRatioByVolume`、`IsRelative`（是否相对交易所收取）。
- 保证金公式：
```
保证金 = 按手数保证金费 × 手数 + 按金额保证金率 × 价格 × 手数 × 合约乘数
多头保证金 = (LongMarginRatioByVolume + LongMarginRatioByMoney × Price × VolumeMultiple) × Volume
空头保证金 = (ShortMarginRatioByVolume + ShortMarginRatioByMoney × Price × VolumeMultiple) × Volume
```
目前国内期货按手数保证金费均为 0，仅按金额。`IsRelative` 为 true 表示该值是相对交易所保证金率的（加成），具体以柜台为准。
- 期货公司有的按交易所保证金率收，有的在交易所基础上加若干个百分点（如 +2%），同样资金在不同期货公司可开仓手数不同。

#### 2.5.2 保证金价格类型 MarginPriceType
`ReqQryBrokerTradingParams`（请求 `CThostFtdcQryBrokerTradingParamsField`：BrokerID、InvestorID、CurrencyID）响应 `CThostFtdcBrokerTradingParamsField` 的 `MarginPriceType`：

| 值 | 宏 | 含义 |
|---|---|---|
| '1' | THOST_FTDC_MPT_PreSettlementPrice | 昨结算价 |
| '2' | THOST_FTDC_MPT_SettlementPrice | 最新价 |
| '3' | THOST_FTDC_MPT_AveragePrice | 成交均价 |
| '4' | THOST_FTDC_MPT_OpenPrice | 开仓价 |

规则：**昨仓统一用昨结算价**；今仓由期货公司设置。仿真环境(SimNow)使用昨结算价。
- 价格类型为 1：冻结保证金 = (按手数 + 按金额率×昨结算价×乘数)×手数；成交后冻结→0，占用 = 同值；盘中最新价变化不影响占用，直到下一交易日新结算价。
- 类型为 2（最新价）/3（成交均价）：冻结与占用随最新价/均价动态变化，**只有今仓**保证金才会随行情波动，昨仓不变。
- 类型为 4（开仓价）：冻结用报单价，成交后用成交价；先开先平，平掉先开的部分后，占用保证金按剩余明细的开仓价计算。
- 市价单：冻结保证金用涨跌停价；占用保证金按价格类型。
- 官方 `OnRspQryBrokerTradingParams` 返回 `MarginPriceType`、`Algorithm`、`AvailIncludeCloseProfit` 等柜台参数；其中 `Algorithm` 影响可用资金/盈亏算法。不要脱离 `ReqQryBrokerTradingParams` 结果，普遍宣称排除浮盈或固定采用某一套 `'1'`~`'4'` 解释；具体枚举和当前版本含义以官方头文件/HTML与实际柜台为准。

举例（au2106，昨结算价 391.74，乘数 1000，LongMarginRatioByMoney=0.08，ByVolume=0）：
- 以 396.16 买开 1 手未成交：冻结保证金 = 0.08×391.74×1000×1 = 31339.20；
- 成交后：冻结=0，占用保证金 = 31339.20（日内不变）。

#### 2.5.3 手续费率

| 查询 | 响应结构 | 说明 |
|---|---|---|
| `ReqQryInstrumentCommissionRate` | `CThostFtdcInstrumentCommissionRateField` | 交易手续费率 |
| `ReqQryInstrumentOrderCommRate` | `CThostFtdcInstrumentOrderCommRateField` | 报单手续费（申报费；每报/撤一次收取，目前中金所等有） |
| `ReqQryOptionInstrCommRate` | `CThostFtdcOptionInstrCommRateField` | 期权合约手续费率（含行权/履约手续费） |
| `ReqQryMMOptionInstrCommRate` | 做市商期权合约手续费 | 做市商专用 |
| `ReqQryMMInstrumentCommissionRate` | 做市商合约手续费率 | 做市商专用 |

- 请求：BrokerID、InvestorID 必填；InstrumentID 选填，**留空返回当前持仓合约的费率**（同保证金率）；`ReqQryInstrumentCommissionRate` 请求为 `CThostFtdcQryInstrumentCommissionRateField`（含 ExchangeID，6.x 增加 InvestorUnitID）。
- 响应字段：InstrumentID（**实际可能是品种代码**，如查 IF2009 返回 "IF"：该品种所有合约费率相同时直接设在品种级）、InvestorRange、BrokerID、InvestorID、`OpenRatioByMoney`、`OpenRatioByVolume`、`CloseRatioByMoney`、`CloseRatioByVolume`、`CloseTodayRatioByMoney`、`CloseTodayRatioByVolume`、ExchangeID、BizType、InvestUnitID。
- 公式：
```
开仓手续费  = 成交数量 × (成交价 × 合约乘数 × OpenRatioByMoney + OpenRatioByVolume)
平昨手续费  = 成交数量 × (成交价 × 合约乘数 × CloseRatioByMoney + CloseRatioByVolume)
平今手续费  = 成交数量 × (成交价 × 合约乘数 × CloseTodayRatioByMoney + CloseTodayRatioByVolume)
```
- 交易所手续费率不能通过 API 查，需看交易所结算参数。
- 大商所“短线开平仓”指今开今平，即平今。
- 中金所手续费 = 交易手续费 + 申报费（OrderCommRate：`OrderCommByVolume`、`OrderActionCommByVolume`，按手数）。
- 查合约手续费率常见失败：查询对象不存在费率设置，返回空（需在期货公司端设置）。

#### 2.5.5 保证金优惠与算法
- **上期所大额单边保证金**：同一品种所有合约按多、空分别累计保证金，只收较大的一边。判断是否适用：`MaxMarginSideAlgorithm`；当前占用：`ReqQryInvestorProductGroupMargin`。
  例：总资金 200,000；au2106 多头占用 100,000，au2102 空头占用 80,000 → 实际占用 100,000，可用 100,000；再成交 1 手 au2104 空头占用 30,000 → 空头合计 110,000 > 多头 100,000，实际占用 110,000，可用 90,000。
- **中金所**：股指期货（IF、IH、IC、IM）跨品种双向持仓按交易保证金单边较大者收取；国债期货亦有跨品种单向大边制度。
- **大商所、郑商所**：普通合约双边收取；标准套利合约只收两腿保证金中较高者；盘中申请组合成功后有大边保证金优惠；收取方式由交易所规则决定。
- **组合保证金**（SPBM/SP-SPAN 等）：部分交易所对期权/期货组合按风险收取，见 2.5.7 和《07_期权与组合合约》。
- 以上优惠体现在柜台算出的 CurrMargin 中；本地估算 UseMargin 为“无优惠逐笔”口径，汇总后会比柜台偏大，需用查询值或交易所规则调整。

#### 2.5.6 保证金率变动与交易所 vs 投资者保证金
保证金率不是常数。常见调整：节假日前、单边市（涨跌停板）、极端风险/市场震荡、持仓量达到一定数量、临近交割月、其他交易所规定。调整后：
- 新持仓/冻结按新率；老持仓是否追加按交易所/期货公司规则（交易所调整在结算时统一重算占用）。
- 交易所保证金（ExchangeMargin、ExchMargin）与投资者/柜台当前保证金（CurrMargin、UseMargin、Margin）是不同口径；公司调整、优惠、价格类型和汇总算法都可能造成差异，不能默认相等，必须结合 `ReqQryInstrumentMarginRate`、`ReqQryExchangeMarginRate` 和账户快照核对。
- 期货公司对保证金率另有“上浮”（如交易所率+1%~3%）、节假日临时调高，应使用定期/每日开盘前重查的值。（工程建议）

#### 2.5.7 期权保证金与手续费（期货期权）
（以下对应期货期权，CTP 后台 V6.3.0 起的规则；更多合约代码与组合见《07_期权与组合合约》。）

**合约代码格式**：上期所、郑商所 = 标的期货合约代码 + C/P + 行权价（如 SR301C5300、cu1408C56000）；大商所、中金所 = `KKYYMM-C/P-XXXX`（如 m1412-C-2700、IO1412-C-2300）。郑商所组合：STD（跨式）、STG（宽跨式）、BUL/BER（垂直价差，当时未开放）、PRT（备兑，原则上交易所盘后组合，无组合平仓指令，需分单腿平仓），如 `STD SR401C5200&SR401P5200`。

**买方**：买入开仓无保证金，但支付权利金（CashIn 减少；冻结阶段用 FrozenCash）；权利金增减量 = 成交数量 × 成交价格 × 期权合约乘数。卖出成交（开仓或平仓）获得权利金收入。冻结权利金用报单数量与昨结算价替代成交数量与成交价。

**卖方交易保证金（每手）**：

| 交易所 | 公式 |
|---|---|
| 郑商所、大商所 | 权利金 + max(标的期货合约保证金 − 期权虚值额/2, 标的期货合约保证金/2) |
| 中金所 看涨 | 权利金 + max(标的指数昨收盘价×乘数×调整系数 − 虚值期权保证金优惠比率×虚值额, 最低保障系数×标的指数昨收盘价×乘数×调整系数) |
| 中金所 看跌 | 权利金 + max(标的指数昨收盘价×乘数×调整系数 − 虚值期权保证金优惠比率×虚值额, 最低保障系数×执行价×乘数×调整系数) |
| 上期所 | max{ 标的期货合约保证金 × Delta风险值 + 权利金, 期权最小保证金 × 期权合约乘数 } |

- 标的期货合约保证金 = [标的结算价 × 期货合约乘数 × 标的期货交易所保证金率(按金额) + 标的期货交易所保证金率(按手数)] × 基础商品乘数；交易时段标的结算价一律用昨结算价（中金所用昨收盘价）。
- 看涨虚值额 = max((行权价 − 标的结算价) × 期权合约乘数, 0)；看跌虚值额 = max((标的结算价 − 行权价) × 期权合约乘数, 0)；中金所分别用 (执行价−标的昨收盘价) 与 (昨收盘价−执行价)。
- **权利金部分**：昨仓权利金 = 期权昨结算价 × 乘数（**上期所**为期权昨收盘价与昨结算价的较大值 × 乘数）；新仓权利金 = 价格(昨结算价或成交价) × 乘数，由 `ReqQryBrokerTradingParams` 返回的 `OptionRoyaltyPriceType` 决定；**委托冻结保证金时一律使用昨结算价**。上期所“期权最小保证金”无论昨仓或新仓都用昨日结算时发布的值。

**CTP 统一归纳**（交易所口径与投资者口径同构，仅费率不同）：
```
每手卖方交易保证金(交易所) = MAX(权利金 + ExchFixedMargin, ExchMiniMargin)
每手卖方交易保证金(投资者) = MAX(权利金 + FixedMargin,     MiniMargin)
```
除上期所外 MiniMargin / ExchMiniMargin 为 0。“不变部分”(FixedMargin 等) 因使用昨日价格，日内为常量，可直接通过 `ReqQryOptionInstrTradeCost` 查得，因此**终端只需自己计算权利金部分**。

`ReqQryOptionInstrTradeCost`：请求 BrokerID、InvestorID、InstrumentID（可空→返回所有持仓合约）、HedgeFlag、InputPrice；响应 `CThostFtdcOptionInstrTradeCostField`：FixedMargin（投资者期权合约保证金不变部分）、MiniMargin（投资者期权合约最小保证金）、Royalty（期权权利金）、ExchFixedMargin、ExchMiniMargin。

**郑商所期权组合保证金优惠**：①买入跨式/宽跨式组合不收保证金；②卖出跨式/宽跨式组合 = 卖看涨与卖看跌保证金中较大者 + 另一部位的权利金；③备兑看涨/看跌期权保证金 = 权利金 + 期货交易保证金。

**期权手续费**：计算方式同期货，另增加执行（行权）手续费，通过 `ReqQryOptionInstrCommRate` 查询。

**注意**：查询期货手续费率、期货保证金率、期权手续费率、期权交易成本时，InstrumentID 允许为空，此时返回该投资者**所有持仓合约**的对应值。

期权持仓盈亏、平仓盈亏为 0，盈亏体现在权利金收支 CashIn；期权行权/放弃行权另有 StrikeFrozen、AbandonFrozen 冻结字段。
   - **API 内置在途流控：同一时刻仅允许 1 笔在途查询**，上一笔未收完全部响应（`bIsLast=true`）前不能发下一笔，否则请求函数**返回 -2**（未处理请求超过许可数），请求不会发出；此限制与前置配置无关，永远存在；
