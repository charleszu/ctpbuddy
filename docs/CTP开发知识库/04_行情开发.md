# 04 行情开发（MdApi）

> 范围：MdApi 的创建/注册/登录/订阅、行情推送规则、深度行情字段、行情模式、现手/增仓/开平/对手盘计算、K线合成、盘后行情、常见问题、断线重连与数据校验、示例代码。
> 参考表见《13_API方法速查表》《15_枚举常量速查表》《14_错误码速查表》《16_结构体字段速查表》。

## 1. 要点速查表

| 主题 | 要点 |
|---|---|
| 创建 | `CreateFtdcMdApi(flowPath, bIsUsingUdp, bIsMulticast, bIsProductionMode)`；flow 目录须提前创建 |
| 流程 | CreateFtdcMdApi → RegisterSpi → RegisterFront(tcp://) → Init → OnFrontConnected → ReqUserLogin → OnRspUserLogin → SubscribeMarketData → OnRtnDepthMarketData |
| 登录 | 默认不校验密码；`LoginVerify` 开启时需先登录交易，BrokerID/UserID 一致 |
| 订阅 | 全市场须逐个填合约；应答可能总是 `CTP:No Error`；大量订阅须分批（每 1000 个延迟 1 秒） |
| 频率 | 快照 2 Tick/秒（500ms），有更新才推，不是逐笔 |
| 无效值 | `1.7976931348623157e+308` 表示字段无值 |
| 累计量 | `Volume`/`OpenInterest`/`Turnover` 为交易日累计，现手/增仓用差分 |
| 均价 | 非郑商所 `AveragePrice` 需除以合约乘数 |
| 日期 | 夜盘 TradingDay/ActionDay 各所不一致 |
| 重连 | API 自动重连（6.7.9+ 固定 1 秒），重连后须重新登录并重订 |
| 没有 | 合约查询、K 线、历史行情、现手/增仓、主力合约 |

## 2. 详细说明
### 2.1 MdApi 创建/注册/登录

#### 2.1.1 接口组成

- 行情 API 与交易 API 完全独立（Python 仅需 `thostmduserapi` 相关文件；C++ 为 `ThostFtdcMdApi.h` + 行情动态库）。回调基类 `CThostFtdcMdSpi`，接口类 `CThostFtdcMdApi`。
- 方法（完整表见《13_API方法速查表》）：`CreateFtdcMdApi`、`GetApiVersion`、`Release`、`Init`、`Join`、`GetTradingDay`、`RegisterFront`、`RegisterNameServer`、`RegisterFensUserInfo`、`RegisterSpi`、`SubscribeMarketData`、`UnSubscribeMarketData`、`SubscribeForQuoteRsp`、`UnSubscribeForQuoteRsp`、`ReqUserLogin`、`ReqUserLogout`、`ReqQryMulticastInstrument`。
- 回调：`OnFrontConnected`、`OnFrontDisconnected(nReason)`、`OnHeartBeatWarning`、`OnRspUserLogin`、`OnRspUserLogout`、`OnRspQryMulticastInstrument`、`OnRspError`、`OnRspSubMarketData`、`OnRspUnSubMarketData`、`OnRspSubForQuoteRsp`、`OnRspUnSubForQuoteRsp`、`OnRtnDepthMarketData`、`OnRtnForQuoteRsp`。
- 行情 API 没有合约查询功能（仅有仅限组播前置的 `ReqQryMulticastInstrument`），不推 K 线、不提供历史行情、不提供现手/增仓。

#### 2.1.2 CreateFtdcMdApi

```cpp
static CThostFtdcMdApi *CreateFtdcMdApi(const char *pszFlowPath = "", const bool bIsUsingUdp = false, const bool bIsMulticast = false, bool bIsProductionMode = true);
```

- `pszFlowPath`：保存订阅/流状态文件的目录，默认当前目录。**目录必须事先创建**，否则报 `RuntimeError: can not open CFlow file in line 279 of file ...ThostFtdcUserApiImplBase.cpp`。（工程建议：多个 MdApi 实例/行情与交易 API 使用不同的 flow 目录，避免流文件互相覆盖。）
- `bIsUsingUdp`/`bIsMulticast`：见 2.5；组播行情只能在内网使用，需确认所连系统支持组播。
- `bIsProductionMode`：true=生产版 API，false=评测版 API（旧版接口无此参数，6.x 新增）。
- mdfront 的 ini 中 `ThostChannelModel`、`ThostUsingMulticast` 决定对客户端的连接模式：`tcp`→TCP 模式（客户端 TCP）；`udp`+`ThostUsingMulticast=no`→UDP 模式（客户端 TCP 或 UDP）；`udp`+`yes`→组播模式（客户端组播）。

#### 2.1.3 注册与初始化

- `RegisterFront(char *pszFrontAddress)`：格式 `protocol://ip:port`，如 `tcp://127.0.0.1:17001`；TCP/UDP/组播行情均写 `tcp://`。可多次调用注册多个前置（地址池）。
- `RegisterNameServer(char*)`：格式同上，**优先于 RegisterFront**；`RegisterFensUserInfo` 配合名字服务器使用。
- `RegisterSpi(pSpi)`：注册回调实例；`Init()`：启动工作线程，调用后接口才开始工作；`Join()`：阻塞等待接口线程结束（可用 sleep/事件循环代替）。
- `GetTradingDay()`：**仅登录成功后**才能得到正确的交易日。`GetApiVersion()`：获取 API 版本。
- 版本要求：连接生产或 simnow 时 API 版本必须与后台匹配（如常见的 6.3.15 对应的生产/仿真环境），版本不对会没有 `OnFrontConnected` 回调、不停断开或无反应。
- `Release()`：不再使用时调用；禁止在 SPI 回调线程内调用（工程建议：`RegisterSpi(NULL)` → `Release()` → 置空指针 → 释放 SPI；创建与释放在同一线程）。

#### 2.1.4 登录 ReqUserLogin

- 必须在 `OnFrontConnected` 之后发起；响应 `OnRspUserLogin`。**登录成功后才能订阅**。
- 行情登录默认不校验账号密码；自 6.6.2 后台支持行情登录身份校验：启用时（前置配置 `LoginVerify=yes`）要求当前交易日该 `UserID`+IP 已成功登录过交易系统，且 `BrokerID`、`UserID` 必须与交易登录一致，否则报“CTP:不合法的登录”。故需要“先登录交易，再登录行情”。
- 登录频率：`LoginFreq`（默认 1，每 session 每秒 1 次；0 不限）超限报“CTP: api login over limit freq”。
- 请求字段（`CThostFtdcReqUserLoginField`，见《16》）：`TradingDay`、`BrokerID`、`UserID`、`Password`、`UserProductInfo`、`InterfaceProductInfo`、`ProtocolInfo`、`MacAddress`、`OneTimePassword`、`ClientIPAddress`（系统自动获取，填写无效）、`LoginRemark`（可被系统日志查询）。`nRequestID` 无递增规则，由用户自行维护。
- 返回值：`0` 成功发送；`-1` 网络连接失败；`-2` 未处理请求超过许可数；`-3` 每秒发送请求数超过许可数。返回非 0 时请求并未发出（工程建议：sleep 后重试）。
- `ReqUserLogout` / `OnRspUserLogout`：登出。

### 2.2 订阅/退订/询价订阅

#### 2.2.1 SubscribeMarketData / UnSubscribeMarketData

```cpp
virtual int SubscribeMarketData(char *ppInstrumentID[], int nCount) = 0;
virtual int UnSubscribeMarketData(char *ppInstrumentID[], int nCount) = 0;
```

- 应答 `OnRspSubMarketData` / `OnRspUnSubMarketData`（参数 `CThostFtdcSpecificInstrumentField` 含 `InstrumentID`，`pRspInfo`）；订阅成功后行情经 `OnRtnDepthMarketData` 推送。
- 返回值同 ReqUserLogin：0/-1/-2/-3。
- **订阅全市场必须逐一填入全部合约代码**，填空不能订阅全市场。
- **无论订阅什么合约代码，应答都可能是“CTP:No Error”**；只有合约代码正确且未过期才会有行情，不要把订阅成功当作有行情。
- 订阅不能回放全天行情，只推送最新行情。无历史行情、断线期间的行情不回补。
- 已知现象：`OnRtnDepthMarketData` 的响应数可能少于请求合约数，应答中可能多次 `bIsLast=true`，不影响实际订阅数量。
- 一次订阅过多合约（期货+期权全部）可能触发 `OnSessionDisconnected`/`OnFrontDisconnected(4097)`：行情前置对每个 session 发送缓存有限制，瞬间发送过多超出缓冲区触发自我保护而断开。**应分批订阅，例如每订阅 1000 个延迟 1 秒。**
- 重复订阅同一合约的处理：应用层应自行去重（工程建议：维护已订阅集合，重连登录后只对集合重订一次）。

#### 2.2.2 询价订阅 SubscribeForQuoteRsp / UnSubscribeForQuoteRsp

- 订阅询价，应答 `OnRspSubForQuoteRsp`（退订 `OnRspUnSubForQuoteRsp`），成功后通过 `OnRtnForQuoteRsp(CThostFtdcForQuoteRspField*)` 推送询价通知；返回值同上。示例合约如 `sc1801`。询价/做市业务见交易开发相关章节。

### 2.3 推送频率与规则

- CTP 转发交易所行情，推送的是**切片（快照）数据，不是逐笔 tick**；上期所、能源中心、中金所、大商所为 **2 Tick/秒（约 500ms 一次）**；郑商所自六期起也仅支持 2 Tick/秒（早期可配置 4 Tick/秒，即 250ms）。业内习惯把快照称 tick。
- **有更新才推**：合约在切片间隔内无变化则不推送，冷门合约可能很久才有一笔。
- 订阅/连接后会先推送该合约最近一笔（最新）行情作为初始行情，之后按有更新推送；推送时刻不严格对齐 .000/.500。
- 集合竞价（开盘前）期间也有行情推送，字段含义以交易所实际推送为准；集合竞价时段不可使用 FAK/FOK 报单。
- 日盘启动时 CTP 会重演夜盘流水，故日盘盘前可能再次收到夜盘行情；日盘结束后会收到交易所结算完成发出的、含当日结算价的行情（约 15:00~15:30，参见 2.8）。建议按交易时间过滤非盘中行情。
- 行情流控与限制（配置在行情前置，见 2.9.3）。
### 2.4 深度行情字段详解

行情由 `OnRtnDepthMarketData(CThostFtdcDepthMarketDataField*)` 推送。完整字段类型见《16_结构体字段速查表》，此处说明语义与处理。

#### 2.4.1 字段分组

| 分组 | 字段 | 说明 |
|---|---|---|
| 标识 | `TradingDay`、`InstrumentID`、`ExchangeID`、`ExchangeInstID`、`ActionDay` | 交易日、合约代码、交易所代码、合约在交易所的代码、业务日期（自然日） |
| 价格 | `LastPrice`、`PreSettlementPrice`、`PreClosePrice`、`OpenPrice`、`HighestPrice`、`LowestPrice`、`ClosePrice`、`SettlementPrice`、`UpperLimitPrice`、`LowerLimitPrice`、`AveragePrice`、`BandingUpperPrice`、`BandingLowerPrice` | 最新价、上次结算价、昨收盘、今开盘、最高、最低、今收盘、本次结算价、涨停板价、跌停板价、当日均价、上带价、下带价 |
| 量/额/仓 | `Volume`、`Turnover`、`OpenInterest`、`PreOpenInterest` | 累计成交量、累计成交金额、持仓量、昨持仓量 |
| 虚实度 | `PreDelta`、`CurrDelta` | 昨/今虚实度（期权相关） |
| 时间 | `UpdateTime`、`UpdateMillisec` | 最后修改时间（HH:MM:SS）、毫秒 |
| 五档 | `BidPrice1~5`、`BidVolume1~5`、`AskPrice1~5`、`AskVolume1~5` | 申买/申卖价量；普通免费行情通常仅一档有值，多档需期货公司开通（上期所/能源中心的多档一般免费，其他交易所多为收费） |

#### 2.4.2 无效值（DBL_MAX）

- 价格类字段出现 `1.7976931348623157e+308`（double 上限，`DBL_MAX`）表示**该字段无值**，不是真实数据。典型场景：盘中 `SettlementPrice`、`ClosePrice` 无效；涨停板时无卖价，`AskPrice1` 为 DBL_MAX 且 `AskVolume1=0`；跌停板同理买价无效。
- 处理（工程建议）：入库/计算前统一判定 `v >= 1e300`（或 `== DBL_MAX`）并置为 NaN/None，避免污染指标、K线和资金计算；不要用 `!= 0` 判有效。
- 连上前置后收到的涨跌停价为 0：可能连接的是级联的 mdfront 且上下级版本不匹配，需核对前置版本。

#### 2.4.3 不同交易所的差异

| 项 | 说明 |
|---|---|
| `ExchangeID` | 期货普通前置不推送；期货 mdfront 推送；个股普通前置推送 |
| `TradingDay` | 郑商所行情中是自然日，其他交易所为交易日（夜盘时尤其要注意）；郑商所 UDP 行情的 `TradingDay` 为空（TCP 行情中由 CTP 补填） |
| `Turnover` | 郑商所：成交金额=成交均价×成交数量（Level1 不推送，由 CTP 计算，近似值）；其他交易所：成交金额=成交均价×成交数量×合约乘数。普通前置后台版本 6.7.1 之前，郑商所口径为 均价×数量；6.7.1 及之后为 均价×数量×合约乘数；组播前置 mdfront 仍为 均价×数量 |
| `AveragePrice` | 仅郑商所推送（已按最小变动价位四舍五入）；其他交易所不推送，TCP 行情由 CTP 按 成交金额/成交数量 自行计算，**需再除以合约乘数 `VolumeMultiple`** 才是真实均价（交易所官网口径=成交金额/成交数量/合约乘数）；UDP 行情不推送 `AveragePrice` |
| `UpperLimitPrice`/`LowerLimitPrice` | 郑商所套利合约涨跌停板价由 CTP 计算，交易所不发 |
| `UpdateMillisec` | 上期所/能源中心/中金所仅 0 或 500 两种值；大商所为切片真实毫秒；郑商所恒为 0 |
| `SettlementPrice` | 郑商所盘中也会送出但盘中不变；郑商所夜盘收盘后会推送结算价（故次日早盘开盘前可能收到结算价）；白盘收盘后也推送全部合约最新结算价；CTP 对该字段不做处理，直接转发。无夜盘合约盘中不会收到结算价 |

#### 2.4.4 Turnover 可能“减少”

郑商所 Level1 的成交额是 CTP 以当日均价和成交量合成的近似值，而均价被按 `PriceTick` 四舍五入。当均价恰好下调一个最小变动价位且成交量增加较少时，新快照的成交额会小于前一快照（如 RM409 均价 2751→2750，成交额 18203367→18199500）。郑商所 Level2 由交易所直接推送成交额，则不会出现。（工程建议：不要假设 Turnover 单调递增；计算分段成交额用差分时对负值截断或改用 成交量×价格 估算。）

#### 2.4.5 持仓量对不上

T 日收盘 `OpenInterest` 与 T+1 日 `PreOpenInterest` 可能不一致：交易所存在大宗/非盘中交易方式产生的持仓，盘中公示、盘后才汇总到行情中。

#### 2.4.6 其他字段口径

- `Volume`、`OpenInterest`、`Turnover` 为交易日内累计值；`Volume` 差分即切片成交量。
- 组合合约行情：仅大商所和郑商所有；仅买卖价量、涨跌停板等少数字段有值，最新价、成交额、成交量等多无值。大商所实际只推单腿行情，组合行情需自行用两腿价差计算；部分终端的组合最新价是终端自算的。
- 期货与期权合约在郑商所、大商所、广期所等的 Level1/Level2 差异：

| 项目 | 郑商所 L1 | 郑商所 L2 | 大商所/广期所 L1 | 大商所/广期所 L2 |
|---|---|---|---|---|
| 发布间隔 | 250ms（可配置 4tick/s 或 2tick/s） | 250ms | 500ms | 250ms |
| 推送频率 | 1秒4次（6.x 起 CTP 仅支持 2tick/s） | 1秒4次 | 1秒2次 | 1秒4次 |
| 买卖档位 | 一档 | 五档 | 一档 | 五档 |
| L2 额外数据 | - | 委买/卖总量、成交金额等 | - | 最佳买卖价位上前10笔分笔委托量、加权平均委买/卖价、实时结算价、分价位成交量统计 |

  上期所/中金所/能源中心 L1 与 L2 发布间隔 500ms（能源 L2 250ms），无额外 L2 数据。CTP 一般只提供 L1（郑商所自六期起仅 2Tick/秒）；多档行情需向期货公司咨询。
### 2.5 行情模式（TCP/UDP/组播）

#### 2.5.1 模式选择

`CreateFtdcMdApi(const char *pszFlowPath = "", const bool bIsUsingUdp = false, const bool bIsMulticast = false, bool bIsProductionMode = true)`

| 行情类型 | bIsUsingUdp | bIsMulticast |
|---|---|---|
| TCP | false | false |
| UDP | true | false |
| 快速行情（组播） | true | true |

- 无论 TCP/UDP/组播，`RegisterFront` 均使用 `tcp://ip:port` 格式；UDP 传输不可靠，因此登录、订阅、接收第一次行情仍使用 TCP，不必为 UDP 另配节点，UDP 仍使用同一地址与端口。
- 交易 API 的该参数缺省/false；行情实例按上表设置。
- UDP 行情不推送 `AveragePrice`，郑商所 UDP 行情中 `TradingDay` 为空（TCP 行情中由 CTP 补填）。
- 组播（快速行情）需连接支持组播的 mdfront，且接收端必须位于内部网络并加入组播组；组播前置的郑商所成交金额仍为 均价×数量（不含合约乘数）。
- 组播合约查询 `ReqQryMulticastInstrument` 仅新的组播 mdfront 支持，普通前置与老 mdfront 调用不会返回有效数据；结构体 `CThostFtdcQryMulticastInstrumentField`（含 `TopicID`、`InstrumentID`）、响应 `OnRspQryMulticastInstrument(CThostFtdcMulticastInstrumentField*)` 见《16_结构体字段速查表》。

#### 2.5.2 协议方式接收二代组播行情（自行解码）

- 术语：协议方式=不使用 CTP API，自行按二代行情协议规范解码；二代组播行情=交易所以组播提供的实时五档行情；mdfront=接收交易所二代组播行情的 CTP 组件。
- 交易所不允许投资者直连报盘网，期货公司可转发二代行情。二代行情含快照查询与增量实时推送，增量只含变动值；期货公司只能转发增量，不能转发快照查询；增量报文里合约用数字编号（InstrumentNo），而 CTP 行情用合约代码（如 rb2002）。
- 拼装完整行情需三部分：增量行情 + 行情快照（来自 mdfront 的完整行情，作基准）+ 组播合约映射（`ReqQryMulticastInstrument` 返回 InstrumentID↔InstrumentNo）。
- 基准快照确定：
  - 盘前接入：开盘后 CTP 推每 tick 快照、转发行情推每 tick 增量；比较同一合约两边 `UpdateTime`+`UpdateMillisec`，一致时将 mdfront 该笔快照作基准，后续增量在其上叠加。
  - 盘中接入：同上，持续比较直至一致。
  - 盘中丢包：二代行情带行情序号，序号不连续即丢包；应停止拼装，重新按上述方法寻找最新快照。

### 2.6 现手/增仓/开平/对手盘

行情结构体 `CThostFtdcDepthMarketDataField` 不含现手、增仓、开平、对手盘字段，需客户端自行计算。只需 5 个字段：`Volume`、`OpenInterest`、`LastPrice`、`AskPrice1`、`BidPrice1`。`Volume` 与 `OpenInterest` 均为累计量（`Volume` 为交易日内累计成交量），同一合约前后两笔快照相减即得增量。

#### 2.6.1 现手与增仓

```
现手 volume_delta        = 后一笔 Volume - 前一笔 Volume          (>= 0)
增仓 open_interest_delta = 后一笔 OpenInterest - 前一笔 OpenInterest  (可正可负)
```

#### 2.6.2 性质判定（不带方向）

| 性质 | 现手与增仓关系 | 含义 |
|---|---|---|
| 双开 | 现手 = 增仓 > 0 | 多头和空头同时开仓 |
| 开仓 | 现手 > 增仓 > 0 | 主动开仓数量大于平仓数量 |
| 平仓 | 现手 > (-增仓) > 0 | 主动平仓数量大于开仓数量 |
| 换手 | 现手 > 增仓 = 0 | 多头互换或空头互换仓位 |
| 双平 | 现手 + 增仓 = 0（现手>0） | 多头和空头同时平仓 |
| 未知 | 现手 = 增仓 = 0 | 异常情况，仅记录 |

#### 2.6.3 价格方向判定

| 方向 | 条件 |
|---|---|
| 向上 | 后一笔 LastPrice >= 前一笔 AskPrice1，或 后一笔 LastPrice >= 后一笔 AskPrice1 |
| 向下 | 后一笔 LastPrice <= 前一笔 BidPrice1，或 后一笔 LastPrice <= 后一笔 BidPrice1 |
| 不变 | 以上均不满足 |

6 种性质 × 3 种方向共 18 种组合，示例：换手+向上=多换（红）；换手+向下=空换（绿）；双开+向上=双开（红）；平仓+向下=多平（绿）；开仓+向上=多开；开仓+向下=空开；平仓+向上=空平；双平按方向分别为双平（向上/向下）。方向“向上”即买方主动（成交价贴近/等于卖价），“向下”即卖方主动。

#### 2.6.4 对手单拆分（双边口径）

监管要求期货市场成交/持仓数据自 2020-01-01 起统一为单边统计；下述推导按双边量（现手与增仓均为双边计数）说明，换算单边时现手、增仓除以 2。

设 S 为对手单中开平方向相同的操作量，O 为开平方向相反的操作量，则：

```
S + O = volume_delta / 2
S - O = abs(open_interest_delta) - volume_delta / 2
=> S = abs(open_interest_delta) / 2
   O = volume_delta / 2 - S
```

示例：某笔“空平、价格向上”，现手 72、增仓 -56：单边成交 36 手；S = 56/2 = 28，O = 72/2 - 28 = 8。即买方 36 = 28（空头买入平仓，影响仓位）+ 8（空头买入平仓，不影响仓位）；对手方 36 = 28（多头卖出平仓）+ 8（空头卖出开仓，与空平互换）。
### 2.7 K线合成

CTP 不推送 K 线，必须由快照自行合成。K 线要素：Time、Volume、Open、High、Low、Close（可加 OpenInterest），取自 `UpdateTime`、`LastPrice`、`Volume`。

#### 2.7.1 一分钟线基本算法

1. 以 `UpdateTime` 的“分钟”部分判断是否进入新一分钟（与当前 bar 的分钟比较，不同即新 bar）。
2. 新 bar：Open=High=Low=Close=`LastPrice`，bar 时间取 `HH:MM:00`，成交量清零，记录 `OpenInterest`。
3. 否则：High=max(High, LastPrice)，Low=min(Low, LastPrice)，Close=LastPrice，更新 OpenInterest。
4. 成交量：`Volume` 是交易日内累计量，bar 成交量 += max(本笔Volume − 上一笔Volume, 0)（max 兜底防回退/换日）；每笔更新“上一笔 Volume”。3/5/10/15/30 分钟线原理相同。

#### 2.7.2 边界与特殊处理

- **收盘时点**：上午 11:30、下午 15:00（夜盘各品种不同）收盘后仍可能收到 11:30:00.500、15:00:00.500 等行情（含集合竞价撮合后的最后一笔）。需决定归入上一根 bar 还是丢弃；常用做法是 15:00:00 及之前的归入最后一根，之后的按盘后行情处理（见 2.8）。
- **0 秒整快照归属**：有的软件把整分钟 0 秒快照作为新 bar 起点，有的作为上一根终点；此为口径选择，需统一。
- **小时线周期**：有的按自然小时切分（商品期货日盘 09:00~10:00、10:00~11:00、11:00~11:30、13:30~14:00、14:00~15:00，共 5 根），有的按满 1 小时交易时间切分（09:00~10:00、10:00~11:15（中间休市 15 分钟）、11:15~14:15、14:15~15:00，共 4 根）。
- **bar 内新高/新低**：快照 `LastPrice` 可能没捕捉到的价位会体现在 `HighestPrice`/`LowestPrice`。有的软件忽略，仅用 LastPrice；有的软件在 `HighestPrice` 大于此前值时令 bar.High=HighestPrice，`LowestPrice` 小于此前值时令 bar.Low=LowestPrice。快照合成的 K 线必然丢失信息，不必强求与交易软件完全一致。
- **非主力/冷门合约**：长时间无 tick，bar 可能缺失，需决定是否按时间补空 bar（延续上一收盘价、成交量 0）。（工程建议）
- **心跳驱动**：仅在收到 tick 时才能切 bar；若需要 bar 及时收线，应另用定时器按交易时间收线。（工程建议）
- **数据质量**：过滤 `LastPrice` 为 DBL_MAX 或 0、非交易时段的行情、`Volume` 回退。

#### 2.7.3 夜盘跨日与 TradingDay / ActionDay

- `TradingDay` 为交易日，`ActionDay` 为实际自然日。日盘两者一致；夜盘属于下一交易日，例如周五（20190830）21:00 夜盘，`TradingDay`=20190902（周一），`ActionDay`=20190830。
- 各交易所实际实现不一，以 20190830 夜盘为例：

| 交易所 | TradingDay | ActionDay |
|---|---|---|
| 上期所/能源中心 | 20190902 | 20190830 |
| 大商所 | 20190902 | 20190902（两个日期都是交易日） |
| 郑商所 | 20190830 | 20190830（日夜盘均为当天自然日） |
| 中金所 | 无夜盘 | - |

- 因此**不可假设各所一致**；合成 K 线的时间戳不要直接拼接 `TradingDay`+`UpdateTime`。（工程建议：用本地时钟/登录得到的交易日 `GetTradingDay()` 为准；夜盘 21:00~23:59 用当前自然日，00:00 之后的夜盘（跨午夜品种）自然日+1，交易日归属取 `GetTradingDay()` 或下一个工作日。）
- 夜盘跨午夜时，`UpdateTime` 从 23:59:59 变为 00:00:00，分钟判定与成交量差分均不受影响，但以“当日”做分组的逻辑需用交易日而非自然日。
- 日盘开盘前（约 08:55~09:00）：夜盘品种可能在日盘启动时重演夜盘行情；`Volume` 在新交易日开盘时从较小值重新累计，故 `max(diff,0)` 兜底，且应在检测到 `TradingDay` 变化时重置“上一笔 Volume”。（工程建议）

#### 2.7.4 UpdateMillisec

上期所/能源中心/中金所只有 0 与 500 两种值，大商所为实际毫秒，郑商所恒为 0；不要依赖其排序判断同一秒内的先后（工程建议：保留接收顺序号）。

#### 2.7.5 收盘价与结算价

- `ClosePrice`（今收盘）、`SettlementPrice`（本次结算价）盘中为 DBL_MAX（无效），收盘/结算后才有值；不要在盘中将其用于计算。
- 结算价在盘后（一般 16 点前）的快照中提前推出；郑商所有夜盘的品种在夜盘收盘后也会推结算价（见 2.4.3）。

### 2.8 盘后行情

- 收盘（15:00）不代表一天交易结束，盘后仍会推送零星行情，且 `Volume` 可能比 15:00 时更大，原因：
  1. 盘后有期转现等交易，郑商所尤其会在盘后继续推送；
  2. 部分品种有 TAS 交易，盘后继续成交并产生行情；
  3. 期权行权/履约成交记录一般集中显示在 15:00~15:30；
  4. 盘后（一般 16 点前）会推送一次包含当天结算价的行情快照，可提前获取结算价而无需等到结算。
- 日盘结束后的行情为交易所结算完成发出的，结算价为当日结算价，推送时间一般在 3 点~3 点半（夜盘结束后的情形，以实际为准）。
- 日盘盘前（开盘前）也可能收到夜盘行情的重演。
- 处理（工程建议）：按各品种交易时段过滤盘中行情；盘后行情单独用于获取结算价/收盘价，不进入盘中 K 线与信号计算。

### 2.9 订阅常见问题

#### 2.9.1 获取合约列表

- 行情 API 没有合约查询功能；`ReqQryMulticastInstrument` 仅查询组播合约，且仅组播 mdfront 支持。获取合约代码的方法：
  1. 登录交易 API 调用 `ReqQryInstrument` 查询（推荐）；期权可用 `ReqQryInstrument` 后按 `ProductClass` 过滤，或 API 6.5.1 起 `ReqQryClassifiedInstrument`（`ClassType`: `INS_ALL`'0'/`INS_FUTURE`'1'/`INS_OPTION`'2'/`INS_COMB`'3'；`TradingType`: `TD_ALL`'0'/`TD_TRADE`'1'/`TD_UNTRADE`'2'；查询全市场时需填有效值 `THOST_FTDC_TD_ALL` 与 `THOST_FTDC_INS_ALL`，不能填 0）；
  2. 抓取交易所网站可交易合约；
  3. 按交易所合约规则生成（如上期白银为当前月起连续 12 个合约）。
- 品种/合约的名称、最小变动价位等字段由期货公司设置，不同公司可能不同，可能为乱码或不一致，不影响交易；可自建合约信息表。
- CTP 查不到“主力合约”，需根据持仓量、成交量自行筛选，注意换月逻辑。

#### 2.9.2 合约代码规则

| 交易所 | 规则 | 示例 |
|---|---|---|
| 上期所/能源中心 | 小写字母 + 4 位数字 | rb1909 |
| 中金所 | 大写字母 + 4 位数字 | IC1909 |
| 郑商所 | 大写字母 + 3 位数字 | TA001（2020 年 1 月） |
| 大商所 | 小写字母 + 4 位数字 | i2001 |

字母为品种，数字为到期年月；已过期合约无行情。

#### 2.9.3 行情前置流控与限制（前置配置，API 表现）

| 配置项 | 含义 | 超限表现 |
|---|---|---|
| `LoginVerify=yes` | 登录行情要求当日 UserID+IP 已登录交易 | “CTP: 不合法的登录” |
| `LoginFreq=1`（0=不限） | 每 session 每秒登录次数，默认 1 | “CTP: api login over limit freq” |
| `SendingListSize`（默认 10000，实际取 max(10000, 设置值)） | 前置给每个 session 发送缓存包上限 | 超出则主动断开会话（4097 等） |
| `ConnectFreq`（未设置=不限） | 同一 IP 每秒允许的 API 连接请求数（一次 Init 到 OnFrontConnected 算一次，与登录无关） | 被主动断开，触发 `OnFrontDisconnected` |
| `MaxIPSession`（6.7.2P6 起，默认 0 不限，例 10） | 每 IP 活跃 session 数 | 新 session 被断开 |
| `MaxSubInstCnt`（6.7.2P6 起，默认 0 不限） | 每 session 订阅合约数 | 订阅失败，原因 6000“CTP:sub too many insts” |

前置 bin 目录下新建 `whiteiplist` 文件（每行一个 IP）可使指定 IP 不受流控/连接数/订阅数限制。

#### 2.9.4 其他常见问答

- 订阅成功但没有行情：检查合约代码大小写/位数、是否过期、是否在交易时段、是否已登录、该前置是否支持该品种/交易所（部分期货公司前置不含某些交易所）。
- 非交易时段收到行情：见 2.8。
- `Volume` 切片量需差分（见 2.7）；`AveragePrice` 需除以合约乘数（见 2.4.3）。
- 能否获得 level2/历史行情/股票行情：CTP 期货仅 Level1 快照；多档（Level2）行情一般收费（上期所/能源中心多档免费），需向期货公司咨询；不提供历史行情（历史数据需自行录制或第三方）；股票行情需使用股票柜台 API。
- 组合合约行情：只有大商所、郑商所有，字段很少；建议订阅各单腿自行计算价差。

## 3. 标准流程/时序

```
客户端                    MdApi                      行情前置
1 CreateFtdcMdApi(flowPath, udp, multicast) 
2 new Spi，RegisterSpi
3 RegisterFront("tcp://ip:port")  (可多个)
4 Init()  ───────────── 建立连接 ───────────▶
5 ◀─────────────── OnFrontConnected
6 ReqUserLogin ─────────────────────────────▶
7 ◀──────────────── OnRspUserLogin (ErrorID==0, GetTradingDay 可用)
8 SubscribeMarketData(分批) ─────────────────▶
9 ◀──────────────── OnRspSubMarketData (每个合约一次)
10 ◀─────────────── OnRtnDepthMarketData (首笔为最近一笔，之后有更新才推，约500ms)
11 UnSubscribeMarketData ▶ OnRspUnSubMarketData
12 Release()
```

断线重连时序：

```
OnFrontDisconnected(nReason) ──(API 自动重连，6.7.9+ 固定1秒)──▶ OnFrontConnected
   → 必须重新 ReqUserLogin → OnRspUserLogin 成功 → 重新 SubscribeMarketData
```

## 4. 代码范例

### 4.1 C++ 行情 SPI 完整骨架

```cpp
#include "ThostFtdcMdApi.h"
#include <cfloat>
#include <set>
#include <string>
#include <vector>
#include <chrono>
#include <thread>

class MdHandler : public CThostFtdcMdSpi {
public:
    MdHandler(CThostFtdcMdApi* api, std::vector<std::string> ids,
              const char* broker, const char* user, const char* pwd)
        : api_(api), ids_(std::move(ids)), broker_(broker), user_(user), pwd_(pwd) {}

    void OnFrontConnected() override {
        CThostFtdcReqUserLoginField req = {0};
        strncpy(req.BrokerID, broker_.c_str(), sizeof(req.BrokerID) - 1);
        strncpy(req.UserID, user_.c_str(), sizeof(req.UserID) - 1);
        strncpy(req.Password, pwd_.c_str(), sizeof(req.Password) - 1);
        api_->ReqUserLogin(&req, ++reqId_);          // 重连后必须重新登录
    }

    void OnFrontDisconnected(int nReason) override {
        // API 会自动重连，仅记录日志；nReason 为十进制，转十六进制比照
        // 0x1001 读失败 / 0x1002 写失败 / 0x2001 心跳超时 / 0x2002 发送心跳失败 / 0x2003 错误报文
    }

    void OnRspUserLogin(CThostFtdcRspUserLoginField* p, CThostFtdcRspInfoField* info,
                        int, bool) override {
        if (info && info->ErrorID != 0) return;      // 登录失败
        subscribeAll();
    }

    void subscribeAll() {
        const size_t BATCH = 500;                    // 分批，防止缓冲区溢出被断开
        for (size_t i = 0; i < ids_.size(); i += BATCH) {
            size_t n = std::min(BATCH, ids_.size() - i);
            std::vector<char*> arr;
            for (size_t j = 0; j < n; ++j) arr.push_back(const_cast<char*>(ids_[i + j].c_str()));
            while (api_->SubscribeMarketData(arr.data(), (int)n) != 0)
                std::this_thread::sleep_for(std::chrono::seconds(1));  // -2/-3 时重试
            std::this_thread::sleep_for(std::chrono::seconds(1));
        }
    }

    void OnRspSubMarketData(CThostFtdcSpecificInstrumentField* p,
                            CThostFtdcRspInfoField* info, int, bool) override {
        // 注意：错误合约也可能返回 ErrorID==0，不代表有行情
    }

    void OnRtnDepthMarketData(CThostFtdcDepthMarketDataField* d) override {
        if (!d) return;
        auto valid = [](double v) { return v < DBL_MAX * 0.5; };   // 判 DBL_MAX 无效值
        double last = valid(d->LastPrice) ? d->LastPrice : NAN;
        // 入队到业务线程，不要在回调里做耗时操作
    }

private:
    CThostFtdcMdApi* api_;
    std::vector<std::string> ids_;
    std::string broker_, user_, pwd_;
    int reqId_ = 0;
};

int main() {
    // flow 目录需提前创建
    CThostFtdcMdApi* api = CThostFtdcMdApi::CreateFtdcMdApi("./flow_md/");
    MdHandler spi(api, {"rb2510", "IF2509"}, "9999", "000000", "");
    api->RegisterSpi(&spi);
    api->RegisterFront((char*)"tcp://180.168.146.187:10131");
    api->Init();
    api->Join();
}
```

### 4.4 一分钟 K 线合成

```python
class BarBuilder:
    def __init__(self):
        self.bar = None
        self.last_volume = None
        self.trading_day = None

    def on_tick(self, d):
        if d.TradingDay != self.trading_day:       # 换交易日重置累计量基准（工程建议）
            self.trading_day = d.TradingDay
            self.last_volume = None
        if d.LastPrice > 1e300:                    # 无效值
            return
        hh, mm, _ = d.UpdateTime.split(':')
        new_bar = self.bar is None or int(mm) != self.bar['minute'] or int(hh) != self.bar['hour']
        if new_bar:
            self.bar = dict(hour=int(hh), minute=int(mm), open=d.LastPrice, high=d.LastPrice,
                            low=d.LastPrice, close=d.LastPrice, volume=0, oi=d.OpenInterest)
        else:
            b = self.bar
            b['high'] = max(b['high'], d.LastPrice)
            b['low'] = min(b['low'], d.LastPrice)
            b['close'] = d.LastPrice
            b['oi'] = d.OpenInterest
        if self.last_volume is not None:
            self.bar['volume'] += max(d.Volume - self.last_volume, 0)
        self.last_volume = d.Volume
```

### 4.5 现手/增仓/开平判定

```python
def classify(prev, cur):
    vd = cur.Volume - prev.Volume                 # 现手
    od = cur.OpenInterest - prev.OpenInterest     # 增仓
    if vd == od and vd > 0: kind = "双开"
    elif vd > od > 0: kind = "开仓"
    elif vd > -od > 0: kind = "平仓"
    elif vd > od == 0: kind = "换手"
    elif vd + od == 0 and vd > 0: kind = "双平"
    else: kind = "未知"
    if cur.LastPrice >= prev.AskPrice1 or cur.LastPrice >= cur.AskPrice1: dire = "向上"
    elif cur.LastPrice <= prev.BidPrice1 or cur.LastPrice <= cur.BidPrice1: dire = "向下"
    else: dire = "不变"
    # 对手单(双边量)
    S = abs(od) / 2
    O = vd / 2 - S
    return kind, dire, vd, od, S, O
```

|---|---|---|
| Init 后无任何回调（无 OnFrontConnected） | 网络不通；API 版本与后台不匹配（生产/仿真环境需匹配的版本，如 6.3.15）；flow 目录不存在 | telnet 前置地址；换对应版本 API；提前创建 flow 目录 |
| 报 `can not open CFlow file in line 279 ...` | flow 目录未创建 | 创建目录 |
| 登录成功、订阅“成功”但无行情 | 合约代码错/大小写/过期；非交易时段；该前置无此品种 | 核对代码规则；用 ReqQryInstrument 获取代码；检查交易时间 |
| 登录提示“CTP:不合法登录” | 前置开启 `LoginVerify`：未先登录交易，或 BrokerID/UserID 不一致 | 先登录交易再登录行情；一致填写 |
| “api login over limit freq” | 单 session 登录过频 | 降低登录频率（默认 1 次/秒） |
| 订阅全市场后 4097/断线 | 瞬间订阅过多触发前置发送缓冲保护 | 分批订阅（如每 1000 个间隔 1 秒） |
| 订阅失败 6000“sub too many insts” | 超过 `MaxSubInstCnt` | 减少订阅，或联系期货公司加白名单 |
| 一连前置就被断开 | 版本不匹配；`ConnectFreq` 连接数流控；`MaxIPSession` | 核对版本；降低连接频率；白名单 |
| `OnRtnDepthMarketData` 价格是 1.797e+308 | 无效值（盘中结算价/收盘价、涨跌停单边无价） | 按 DBL_MAX 判无效处理 |
| 涨跌停价为 0 | 连接级联 mdfront 且版本不对 | 核对前置版本 |
| 郑商所成交额减少 | 均价按 PriceTick 四舍五入合成成交额 | 不假设单调 |
| 均价/成交额量级不对 | 未除合约乘数；Turnover 口径随版本/前置不同 | 非郑商所 AveragePrice 除以 VolumeMultiple |
| 组合合约无行情或不跳动 | 仅大商所/郑商所有且字段少；大商所仅推单腿 | 订阅单腿自行计算 |
| 盘前/盘后收到行情 | 重演夜盘流水；盘后结算/期转现/TAS/行权 | 按交易时段过滤 |
| 夜盘日期混乱 | 各所 TradingDay/ActionDay 实现不同 | 见 2.7.3，不要直接拼接 |
| K 线与交易软件不同 | 合成口径不同（整点归属、小时切法、HighestPrice 处理） | 统一口径，不强求一致 |
| 断线后收不到数据 | 重连后未重新登录/订阅 | OnFrontConnected 中重新登录，登录成功后重订 |
| 调用 Release 崩溃/死锁 | 在 SPI 线程内 Release | 在外部线程释放 |
| 无法订阅重收全天行情 | 只推最新 | 自行录制 |

## 6. 检查清单

Do:
- 创建 flow 目录并保证唯一；
- OnFrontConnected 内登录，登录成功后再订阅；
- 订阅用实际合约代码、分批、检查返回值（0/-1/-2/-3）；
- 无效值（DBL_MAX）统一过滤；
- 用 `Volume`/`OpenInterest` 差分计算现手/增仓；
- 断线重连后重新登录并重订；
- 按交易时段过滤盘中行情；
- 回调内仅入队，处理放工作线程。（工程建议）

Don't:
- 不要把订阅应答成功当作有行情；
- 不要假设各所 TradingDay/ActionDay 一致；
- 不要假设 `Turnover` 单调递增或 `AveragePrice` 已为真实均价；
- 不要在 SPI 内 Release 或长时间阻塞；
- 不要一次性订阅全市场；
- 不要期望 CTP 提供 K 线、历史行情、现手、主力合约。

断线重连与校验补充：`OnFrontDisconnected` 的 `nReason`：0x1001 网络读失败、0x1002 网络写失败、0x2001 接收心跳超时、0x2002 发送心跳失败、0x2003 收到错误报文（十进制 4097/4098/8193/8194/8195）。API 自动重连（6.7.9 及以后固定间隔 1 秒，间隔不可自定义，也无法关闭自动重连），重连地址可能是原注册地址或其他可用地址；重连后须重新登录。心跳：前置约每 53s、API 约每 15s 发送心跳；超过阈值无数据则断线。持续 4097 的首要原因是 API 与后台版本不匹配（此时重连无用），其次为前置拥挤、`ConnectFreq` 流控、订阅缓冲溢出。数据校验（工程建议）：检查 `InstrumentID` 在订阅集合内、`UpdateTime` 单调不减、`Volume`/`OpenInterest` 不回退、价格在 [`LowerLimitPrice`, `UpperLimitPrice`] 内、`LastPrice` 非 DBL_MAX、买价 ≤ 卖价；重连后将“上一笔”基准重置，避免跨断线差分被误判为大成交。
