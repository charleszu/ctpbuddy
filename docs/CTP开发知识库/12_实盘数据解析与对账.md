# 12 实盘查询数据解析与对账（账户 / 报单 / 成交 / 结算单）

> 本章把真实环境查询结果（`OnRspQryTradingAccount`、`OnRspQryOrder`、`OnRspQryTrade`、`OnRspQrySettlementInfo`）分为官方字段语义、有限本地样本观察和待核事项；不把单一账号/交易日/版式外推为普遍规则。官方字段与回调规则优先回到 [`../api-doc-html/`](../api-doc-html/)，来源考证见 [`../notes/04-资金持仓保证金手续费.md`](../notes/04-资金持仓保证金手续费.md)、[`../notes/09-错单推送面与错误码对账.md`](../notes/09-错单推送面与错误码对账.md)。本次有限样本核对使用 `tools/audit_real_accounts.py` 的默认外部目录，未扫描个人目录；具体环境差异仍待核。

## 1. 四类数据的定位

| 数据 | 回调 / 结构体 | 本质 |
|---|---|---|
| 资金账户 | `OnRspQryTradingAccount` / `CThostFtdcTradingAccountField` | 查询时刻的账户快照（每次查询一条） |
| 报单 | `OnRspQryOrder` / `CThostFtdcOrderField` | 查询时可见的**最新状态快照**，不是状态流水，也不保证是固定终态；中间状态需自己记录 `OnRtnOrder` |
| 成交 | `OnRspQryTrade` / `CThostFtdcTradeField` | 每笔成交一条；一笔报单可对应多笔成交 |
| 结算单 | `OnRspQrySettlementInfo` / `CThostFtdcSettlementInfoField.Content` | 逐日盯市结算单文本，分多条返回，需拼接 |

## 2. 编码与读取

- CTP 字符串原生是 **GBK**（`StatusMsg`、`ErrorMsg`、结算单 `Content` 等）。落盘成 CSV/TXT 时常被转成 UTF-8（可能带 BOM）。读取时先试 `utf-8-sig`，失败再试 `gb18030`（兼容 GB2312/GBK），不要硬编码单一编码。
- 结算单 `Content` 分多条回调返回，**汉字可能被拆在两条的边界上**：必须先拼接**字节**，再整体解码；不可逐条解码后拼接。

```python
def read_text(path):
    b = open(path, 'rb').read()
    for enc in ('utf-8-sig', 'gb18030'):
        try: return b.decode(enc)
        except UnicodeDecodeError: pass
    return b.decode('gb18030', 'replace')
```

## 3. 资金账户字段与恒等式

### 3.1 恒等式（对任意账户日恒成立）

```
Balance(动态权益) = PreBalance + CloseProfit + PositionProfit + CashIn − Commission + Deposit − Withdraw
Available(可用资金) = 按 `ReqQryBrokerTradingParams` 返回的 `Algorithm`、`AvailIncludeCloseProfit`、保证金价格类型及柜台其他参数计算；常见样本可写成 `Balance − CurrMargin − FrozenMargin − FrozenCommission − max(PositionProfit, 0)`，但不能普遍套用。
MortgageableFund(可取资金基数) = Available − max(CashIn, 0) − max(CloseProfit, 0)
WithdrawQuota(可取资金) = MortgageableFund × 取资金比例（柜台参数）
静态权益 = PreBalance + Deposit − Withdraw
```

### 3.2 结论
1. `Balance` 是**动态权益**（含当日盈亏），不是静态权益。
2. `CashIn` 是当日**权利金净收支**（卖期权收入为正，买期权支出为负），计入 `Balance`。
3. `Available` 不能脱离柜台参数作普遍判断：官方 `ReqQryBrokerTradingParams`/`OnRspQryBrokerTradingParams` 明确提供 `Algorithm`、`AvailIncludeCloseProfit`、`MarginPriceType` 等参数；本地样本中可观察到不计入部分浮盈的口径，但不能写成所有环境都排除浮盈、全额扣除浮亏。
4. 当日收到的权利金与平仓盈利**当日不可取**（见 `MortgageableFund` 公式）。
5. 取资金比例因期货公司而异，并可能因出入金当日而临时变化，**必须取自查询结果，不可写死**。
6. 盈亏口径为逐日盯市：`PreBalance` 等于上一交易日**结算后**权益；`PositionProfit` 是当日相对昨结算价（今仓相对开仓价）的浮动盈亏。纯期权持仓无逐日盯市，`PositionProfit` 为 0。
7. 恒为 0（对普通投资者）的字段：`Credit PreCredit Mortgage PreMortgage FrozenCash FrozenSwap RemainSwap Interest InterestBase Reserve ReserveBalance DeliveryMargin ExchangeDeliveryMargin FundMortgage* SpecProductExchangeMargin SpecProductFrozenMargin SpecProductMargin SpecProductPositionProfit*`。
8. `FrozenCommission` 是挂单预估冻结手续费；盘中挂单也可能非 0，不能限定为仅收盘时存在。
9. `SpecProductCommission`、`SpecProductCloseProfit`：等于**能源中心品种**的手续费/平仓盈亏之和，是总额 `Commission`/`CloseProfit` 的**子集**，不可重复相加。
10. `CurrMargin` 是当前保证金总额，`ExchangeMargin` 是交易所保证金；不同公司可能使用不同调整/费率/优惠与价格口径，不能默认相等，必须结合本环境的费率查询和账户结果核对。
11. `PreDeposit` 字段名义为“上次存款额”，**不是通用恒等式，不能当作 `PreBalance` 的别名**。仅在部分接入环境中观察到其取值与 `PreBalance` 相同；跨环境不可依赖，取昨日权益一律用 `PreBalance`（或上一日结算单期末结存）。

### 3.3 与结算单对账
- `Balance − 结算单.期末结存` 可精确分解为各分项差之和（PreBalance、CloseProfit、PositionProfit、CashIn、Commission、出入金）。
- 差异需按环境拆解：API 的 `Commission` 与结算单手续费可能因估算、舍入、申报费及结算时点不同而不同；本地有限样本曾观察到 API 侧偏高，但这是样本观察，不是必然规律。
- `PreBalance` 等于**上一日结算单的期末结存**，而不是上一日 API 查询到的 `Balance`；对账 `PreBalance` 请用结算单。
- 大偏差只有三类原因：①查询发生在**出入金入账之前**；②查询发生在**结算价确认之前**（`PositionProfit`、`CurrMargin`、`Available` 用盘中价格口径）；③取到了**陈旧数据**。
- **规则**：盘后账户查询 ≠ 最终结算结果。含期货隔夜持仓、当日有出入金时二者可能不同；需要权威数值时以结算单为准。

## 4. 报单（OnRspQryOrder）

### 4.1 字段取值结论
| 场景 | 结论 |
|---|---|
| 价格/时间条件 | 限价单为 `OrderPriceType='2'`、`TimeCondition='3'`(GFD)、`VolumeCondition='1'`(AV)、`ContingentCondition='1'`(立即)、`ForceCloseReason='0'` |
| 查询状态 | `OrderStatus` 是查询时最新快照；`'0'` 全部成交、`'5'` 已撤单、`'3'` 未成交仍在队列等均可能出现，不能把查询结果预设为固定终态 |
| 瞬时成交 | **成交极快的订单**（如对手盘已在队列、报单即刻全部成交）会出现 `OrderStatus='0'` 但 `OrderSubmitStatus='0'`，`StatusMsg` 形如“全部成交报单已提交”，`NotifySequence=0`：成交先于交易所“已接受”确认到达所致。**判断成交只看 `OrderStatus`/`VolumeTraded`，不看 `OrderSubmitStatus` 或 `StatusMsg` 文本** |
| 部成部撤 | 终态为“已撤单”（`'5'`）且 `VolumeTraded>0`；成交部分在成交表中。不能把“已撤单”当作未成交 |
| 被拒单 | `OrderSubmitStatus='4'`、`OrderSysID` 为空，`StatusMsg` 带交易所原因（如“当前状态禁止此项操作”，常见于未开盘时报单）。**无 `OrderSysID` 的报单从未进入交易所** |
| 数量关系 | `VolumeTraded = Σ 该单所有成交 Volume`；`VolumeTotal = VolumeTotalOriginal − VolumeTraded` |
| 时间字段 | `CancelTime` 为交易所时间，`InsertTime` 为 CTP 时间，且只到秒，二者相减**不能作为精确延迟**（可为负）；`UpdateTime/SuspendTime/ActiveTime` 常为空 |
| 夜盘归属 | 夜盘报单的 `InsertDate`（自然日）≠ `TradingDay`（归属的下一交易日），周五夜盘归属下周一。**统计某交易日必须按 `TradingDay`** |

### 4.2 标识字段格式
- `OrderSysID`、`OrderLocalID`、`TradeID` 可能是右对齐、带前导空格的定长字符串。分析键可使用 `strip()` 后的规范值；但撤单发送 `OrderSysID` 必须保留并回填官方回报中的 raw 字符串，不能把 trim 值直接发回柜台。`TradeID` 保持字符串语义，不能一律转整数。
- `OrderSysID` 仅在同一交易所同一交易日内唯一；全局唯一键用 `(TradingDay, ExchangeID, OrderSysID)`。
- `TraderID`（交易所席位交易员号）与 `BusinessUnit`、`ActiveTraderID` 在本类数据中相同；它**不是** `TradeID`。
- `ClientID` 是交易所交易编码，每个交易所各一个，同一自然人在同一交易所的多个账号可共用。
- `UserProductInfo` 可用于识别下单终端类型。
- 新版 API（6.7.x 起）把旧字段（如合约代码、IP 地址）挪到 `reserve1/2/3`，实际取值使用新字段 `InstrumentID/ExchangeInstID/IPAddress`。

### 4.3 合约代码规则
| 交易所 | 期货 | 期权 |
|---|---|---|
| 上期所 | `<品种><YYMM>` | `<品种><YYMM><C/P><行权价>`（无分隔） |
| 中金所 | `<品种><YYMM>` | `<品种><YYMM>-<C/P>-<行权价>`（短横线分隔） |
| 能源中心 | `<品种><YYMM>` | `<品种><YYMM><C/P><行权价>`（无分隔） |
| 广期所 | — | `<品种><YYMM>-<C/P>-<行权价>`（短横线分隔） |

### 4.4 不同接入环境的字段差异（占位说明）
同一套 API 对接不同期货公司，返回的**辅助字段**差异很大，不能依赖它们做业务判断：
- 某些接入环境中 `UserID`、`ActiveUserID` 恒为空，`FrontID`、`SessionID`、`SessionReqSeq` 恒为 0，`MinVolume` 为 0，`OrderSubmitStatus` 恒为 3，`StatusMsg` 只有“全部成交/已撤单/未成交”三种，`RequestID` 为大数字。
- 某些环境中 `BranchID`、`IPAddress` 会出现不可打印字符或纯数字，应做**有效性校验**（可打印、长度合法）后再使用。
- 广期所的 `BusinessUnit` 可带前导空格，`TradingRole` 可为空格，形态与上期所/中金所/能源中心不同，不可套用。
- 工程规则：不依赖 `UserID/FrontID/SessionID` 判断“是否本会话单”；撤单优先用 `ExchangeID+OrderSysID`。

## 5. 成交（OnRspQryTrade）

- `Σ成交 Volume = 报单.VolumeTraded`；成交表中每个 `OrderSysID` 都能在报单表找到。
- `TradeID` 仅在交易所当日内唯一，买卖双向各一条同号；唯一键用 `(TradingDay, ExchangeID, TradeID, Direction)`。
- 只有中金所成交带 `TradeType`、`TradingRole`（`'1'` Taker）和 `PriceSource`（`'0'` 前成交价、`'1'` 买价、`'2'` 卖价）；上期所/能源中心通常为空。
- 开平标志：上期所/能源中心区分 `'3'` 平今、`'4'` 平昨；中金所只有 `'0'` 开、`'1'` 平。
- `TradeDate`（自然日）≠ `TradingDay` 的成交即夜盘/凌晨成交。
- 与结算单“成交记录”对账：笔数、手数合计需结合交易日、交易所、合约、方向、开平和环境版式核对；`TradeID` 与结算单“成交序号”可能存在格式差异，先保留 raw，再按本环境已验证的映射比较，不能一律转成整数。
- 用成交 + 开平标志即可重建持仓；平仓盈亏按先开先平：昨仓相对昨结算价，今仓相对开仓价。

## 6. 结算单（OnRspQrySettlementInfo）

### 6.1 文本结构
```
{期货公司名称}
制表时间 Creation Date：YYYYMMDD
交易结算单(盯市) Settlement Statement(MTM)
客户号 Client ID：<账号>   客户名称 Client Name：<姓名>
日期 Date：YYYYMMDD
[公司公告]
资金状况 Account Summary
出入金明细 Deposit/Withdrawal   （当日有出入金才有）
成交记录 Transaction Record     （当日有成交才有）
平仓明细 Position Closed        （当日有平仓才有）
持仓明细 Positions Detail       （有持仓才有）
持仓汇总 Positions              （有持仓才有）
[行权/交割明细、期权到期行权履约通知书 等，视情况出现]
```
区块是否出现取决于当日业务，**解析必须按标题定位并容错缺失**。

### 6.2 资金状况字段（中英对照，格式 `中文 English：数值`）
左列：期初结存 Balance B/F、出入金 Deposit/Withdrawal、平仓盈亏 Realized P/L、持仓盯市盈亏 MTM P/L、期权执行盈亏 Exercise P/L、手续费 Commission、行权手续费 Exercise Fee、交割手续费 Delivery Fee、货币质入 New FX Pledge、货币质出 FX Redemption、质押变化金额 Chg in Pledge Amt、权利金收入 Premium Received、权利金支出 Premium Paid、交割盈亏 Delivery P/L。
右列：基础保证金 Initial Margin、期末结存 Balance C/F、质押金 Pledge Amount、客户权益 Client Equity、货币质押保证金占用 FX Pledge Occ.、保证金占用 Margin Occupied、交割保证金 Delivery Margin、多头期权市值 Market Value(long)、空头期权市值 Market Value(short)、市值权益 Market Value(equity)、可用资金 Fund Avail.、风险度 Risk Degree、应追加资金 Margin Call、货币质押变化金额 Chg in FX Pledge。

### 6.3 已验证恒等式
```
期末结存 = 期初结存 + 出入金 + 平仓盈亏 + 持仓盯市盈亏 + 期权执行盈亏
           − 手续费 − 行权手续费 − 交割手续费 + 权利金收入 − 权利金支出 + 交割盈亏 + 质押变化金额
客户权益 = 期末结存
市值权益 = 客户权益 + 多头期权市值 − 空头期权市值
可用资金 = 客户权益 − 保证金占用 − 交割保证金
风险度   = 保证金占用 / 客户权益
```
结论：
1. 期权市值只进入**市值权益**，不进入客户权益；**卖权策略的真实净值看市值权益**。
2. **出入金以“出入金明细”逐行求和为准**，汇总字段可能与明细不一致。
3. **中金所申报费**以“出入金”类型的一笔出金出现在出入金明细中（说明栏“中金所申报费 出金”），因此 `出入金 = 银期转账净额 − 申报费`。漏算它会使恒等式差出申报费金额。
4. 结算单“可用资金”≠ API `Available`：前者 = 客户权益 − 保证金占用（浮盈已计入权益）；后者不计入浮盈。
5. 不同期货公司/不同时期的结算单版式可能不同（如缺少 `客户权益` 行），解析需容错。
6. **结算单正文的 `日期 Date` 才是真实日期**：若在结算完成前查询，会返回上一份已生成的结算单（内容与上一日完全相同），不能只信请求日期。
7. 期权的 `权利金收支` 合计等于 API `CashIn`；期权的平仓盈亏为 0，盈亏体现在权利金收支（`权利金收支 = ± 成交价 × 手数 × 合约乘数`）。

### 6.4 明细表列
管道符 `|` 分隔，表头中英两行，表尾 `|共 N条|`；底部有缩写对照（`能源中心---INE 上期所---SHFE 中金所---CFFEX 大商所---DCE 郑商所---CZCE 广期所---GFEX`，`开---Open 平---Close 平今---Close Today 强平---Forced Liquidation 平昨---Close Prev. 强减---Forced Reduction 本地强平---Local Forced Liquidation`）。

| 区块 | 列 |
|---|---|
| 出入金明细 | 发生日期｜出入金类型（银期转账/出入金/银期换汇）｜入金｜出金｜汇率｜资金账号｜说明 |
| 成交记录 | 成交日期｜投资单元｜交易所｜交易编码｜品种｜合约｜买/卖｜投/保｜成交价｜手数｜成交额｜开平｜手续费｜平仓盈亏｜权利金收支｜成交序号｜资金账号；表尾含合计 |
| 平仓明细 | 平仓日期｜投资单元｜交易所｜交易编码｜品种｜合约｜开仓日期｜投/保｜买/卖｜手数｜开仓价｜昨结算｜成交价｜平仓盈亏｜权利金收支｜资金账号 |
| 持仓明细 | 逐笔开仓持仓：开仓价、昨结算、结算价、浮动盈亏、保证金 |
| 持仓汇总 | 投资单元｜交易编码｜品种｜合约｜买持｜买开仓均价｜卖持｜卖开仓均价｜昨结算｜今结算｜持仓盯市盈亏｜保证金占用｜投/保｜多头期权市值｜空头期权市值｜资金账号 |

注意：
- “买/卖”列带空格，先 `strip()`。
- **平仓明细的“买/卖”需按环境和版式核验，不能由本库单一规则覆盖**。已查有限本地样本 `20260112/13200265`：原油期权平仓明细出现“卖”，与成交记录的平仓方向、权利金字段共同解释；与现有“被平掉的原持仓方向”概括存在冲突。保留该样本和来源，待按更多交易日/账号及不同期货公司版式核验，不在此处断言通用方向。
- 期货平仓盈亏：昨仓 `(平仓价 − 昨结算价) × 手数 × 乘数`（空头取反），今仓用开仓价。
- 结算单中部/尾部夹带公司公告，不是数据，只处理已知区块标题。

### 6.5 解析示例
```python
import re
LABEL = re.compile(r'([\u4e00-\u9fa5][\u4e00-\u9fa5 ]*?)\s*[A-Za-z][A-Za-z/ ()\.\-:]*?[：:]\s*(-?[\d,]+\.\d+)')
def parse_summary(text):
    head = text
    for k in ('成交记录', '持仓明细', '持仓汇总', '出入金明细'):
        head = head.split(k)[0]
    d = {}
    for m in LABEL.finditer(head):
        d.setdefault(m.group(1).replace(' ', ''), float(m.group(2).replace(',', '')))
    return d

def parse_table(text, title):
    i = text.find(title); rows = []
    for line in text[i:].splitlines()[1:]:
        p = [x.strip() for x in line.split('|')]
        if len(p) > 3 and re.fullmatch(r'\d{8}', p[1] or ''):
            rows.append(p[1:-1])
        elif line.startswith('|共'): break
    return rows
```

## 7. 对账手册（Agent 可直接执行）

1. **键规范化**：分析键可对 `OrderSysID/OrderLocalID` 使用 `strip()`；发送撤单时保留 `OrderSysID` raw；`TradeID` 保持字符串并按环境验证映射。
2. **报单 ↔ 成交**：`Σ trade.Volume == order.VolumeTraded` 应按查询时点和回报补齐情况核对；`VolumeTotal + VolumeTraded == VolumeTotalOriginal` 是字段关系，但撤单终态仍可能保留未成交余量，不能写成终态未成交量必为 0；`OrderSysID` 为空的订单通常不能用交易所键对成交，需结合会话键和回报时序判断。
3. **成交 ↔ 结算单成交记录**：按（合约、买卖、开平、价格、手数、成交序号）对齐；行数 = `共 N条`；手数合计、成交额合计一致。
4. **成交 ↔ 平仓明细**：平仓成交手数合计 = 平仓明细手数合计。
5. **账户 ↔ 结算单**：先按本环境 `ReqQryBrokerTradingParams` 和账户字段做 API 内部自洽，再跨源对账。`Balance − 期末结存` 需拆解查询时点、出入金、结算价、申报费、舍入和手续费口径，不能预设只剩 API 手续费偏差或 API 必然偏高。逐项对账：`CloseProfit↔平仓盈亏`、`CashIn↔权利金收入−权利金支出`、`PositionProfit↔持仓盯市盈亏`、`CurrMargin↔保证金占用`、`Commission↔手续费`，均需标注环境和版式。
6. **完整性**：先核对“哪些日期/账号有数据”，再对数值，避免把缺数据当作不一致。
7. **时间**：统计按 `TradingDay`；夜盘跨自然日；`CancelTime` 与 `InsertTime` 不同源。

### 对账失败速查（现象 → 原因 → 处理）
| 现象 | 原因 | 处理 |
|---|---|---|
| `Balance` 与结算单相差整数万元 | 银期转账/出入金尚未入账即查询 | 结算后重查，或用结算单出入金明细 |
| `PositionProfit`/`CurrMargin`/`Available` 与结算单差较大 | 查询早于结算价确认；浮盈不计入可用 | 结算完成后再查，或接受容差 |
| 结算单正文日期与请求日期不符 | 结算单尚未生成，返回上一份 | 校验正文日期，不符则稍后重查 |
| 成交缺失/多出 | 夜盘按自然日误分日 | 按 `TradingDay` 分组 |
| 订单已全成交但 `OrderSubmitStatus='0'` | 瞬时成交先于确认 | 正常，以 `OrderStatus/VolumeTraded` 为准 |
| `OrderSysID` 匹配不上 | 前导空格 | `strip()` |
| `UserID/FrontID` 为空 | 该接入环境不填充 | 不依赖这些字段 |
| 手续费对不上 | API 估算含舍入/申报费口径 | 以结算单为准 |
