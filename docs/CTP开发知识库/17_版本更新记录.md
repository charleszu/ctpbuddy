### 1.1 6.7.13（后台 V6.7.13，2026-02-25）

**新增/修改接口**
1. 后台V6.7.12优化（并入此版本说明）：`ReqQryBrokerTradingParams` 返回的盈亏算法 `Algorithm` 值优化；对本就不支持的组合合约的条件单、预埋单、预埋撤单业务，返回明确报错（见 error.xml）。
2. **投资者登录双因素认证（短信）**：
   - 新增 `ReqGenSMSCode` / `OnRspGenSMSCode`（申请短信验证码），请求中 `BrokerID`、`UserID`、`Mobile` 必填。
   - `CThostFtdcReqUserLoginField` 增加 `TThostFtdcSMSCodeType SMSCode`（短信验证码）。
   - 新错误码：

| ErrorID | 标识 | 含义 |
|---|---|---|
| 6014 | MOBILE_NOT_MATCH | 非预留手机号 |
| 6015 | SMSVERIFY_NOT_CONFIG | 该用户没有开启短信验证 |
| 6016 | DUP_SMSCODE_GEN_REQ | 重复的申请验证码请求 |
| 6017 | SMSCODE_MISMATCH | 验证码不匹配 |
| 6018 | SMSCODE_USED | 验证码已经使用过 |
| 6019 | SMSCODE_OUTOFTIME | 验证码已过期 |
| 6020 | SMSCODE_NEEDED | 已开启短信认证，请填写短信验证码 |
| 6021 | DR_SMSVERIFY_NOT_CONFIG | 该中心未配置短信验证功能 |
| 6023 | AFTER_LOGIN | 已登录成功，不允许申请验证码 |

3. **私有流订阅调整**：`SubscribePrivateTopic` 入参增加 `int nSeqNo`（不填默认为1）；`THOST_TE_RESUME_TYPE` 新增 `THOST_TERT_RESUME_FROM_SEQ_NO`，支持从指定序号开始重传，未填序号默认从序号1开始。
4. **新增回调** `virtual void OnRtnPrivateSeqNo(int nSeqNo)`：参数为“即将被处理的私有流序号”（可用于断点记录）。
5. **中继上报用户信息** `RegisterUserSystemInfo` 新增 `TThostFtdcDeviceTagType MAC`。监管字段已独立：中继终端应规范填写 `ClientPublicIP`、`ClientAppID`、`MAC`，`ClientLoginRemark` 建议格式 `"UUID|手机号.."`，均填终端投资者信息；后续CTP可能将这三个字段由非必填改为必填。
6. **郑商所套利确认 / 套保确认**（交易所仍在盘后结算才能确认）：

| 业务 | 请求 | 响应 | 通知 | 错误回报 |
|---|---|---|---|---|
| 套利确认 | ReqSpdApply | OnRspSpdApply | OnRtnSpdApply | OnErrRtnSpdApply |
| 套利确认查询 | ReqQrySpdApply | OnRspQrySpdApply | — | — |
| 套利确认撤销 | ReqSpdApplyAction | OnRspSpdApplyAction | — | OnErrRtnSpdApplyAction |
| 套保确认 | ReqHedgeCfm | OnRspHedgeCfm | OnRtnHedgeCfm | OnErrRtnHedgeCfm |
| 套保确认查询 | ReqQryHedgeCfm | OnRspQryHedgeCfm | — | — |
| 套保确认撤销 | ReqHedgeCfmAction | OnRspHedgeCfmAction | — | OnErrRtnHedgeCfmAction |

   - 时序：申请/确认——CTP校验通过给 Rtn 通知；未通过给 Rsp 响应和 ErrRtn；交易所回报后再给 Rtn（交易所校验未通过**没有** ErrRtn）。撤销——CTP通过给 Rtn，未通过给 Rsp+ErrRtn；交易所未通过**会有** ErrRtn。
   - 错误码：6007 未找到套利申请记录；6008 套利申请已撤销，不能重复撤销；6009 未找到套保申请记录；6010 套保申请已撤销，不能重复撤销。
7. **期权到期日盘后禁止终端行权/自对冲时段**：柜台可设置，新增 6022（该时间为到期日盘后禁止客户端自对冲时间，禁止申报）。
8. **采集库**：增加 `blkid` 指令补充采集云服务器硬盘序列号；Windows 版本增加 `Get-CimInstance` 采集 CPU/BIOS/磁盘序列号（高版本Windows不再支持 wmic）。
9. `OnRspQryContractBank` 增加 `TThostFtdcBankIDType csrcBankID`（上报csrc的银行代码）。
10. **不涉及API修改但有影响的后台优化**：
    - 上期能源**市价指令**：`LimitPrice` 填“保护价”，`OrderPriceType` 填“任意价”。
    - 上期能源**套利指令**：`CombOffsetFlag`、`CombHedgeFlag` 需输入两位，如 `CombOffsetFlag='04'`（左腿开、右腿平昨），`CombHedgeFlag='13'`（左腿投机、右腿套保）；`CombOffsetFlag='01'` 的平仓会自动转为平昨；`IsSwapOrder` 对上期所无效（即使两腿开平不同也填false）。
    - 可开可平手数：市价指令按保护价算保证金；套利指令的 TraderApi 最大可下单手数查询暂不支持两位开平标志，需分别查单腿取最小值。
    - 交易所规则：上期能源市价、套利指令仅在合约“连续交易”状态可报入；集合竞价阶段仅允许撤销转限价后的市价单或套利合约报单，不允许报入市价/套利指令。
    - 广期所履约对冲可不指定合约（合约代码可不填）。

**兼容性提醒**：新增 SMSCode 字段改变登录结构体布局，必须使用匹配版本的头文件重新编译；柜台开启短信认证后未填 SMSCode 将报 6020。

### 1.3 6.7.11（后台 V6.7.11，2025-06-17）
- **评测版与生产版合并**：交易与行情API均增加 `bool blsProductionMode` 默认参数（true=生产模式，默认；false=测评模式）。
```cpp
CreateFtdcTraderApi(const char *pszFlowPath = "", bool blsProductionMode = true);
CreateFtdcMdApi(const char *pszFlowPath = "", const bool blsUsingUdp = false,
                const bool blsMulticast = false, bool blsProductionMode = true);
```
  不修改默认值则接入生产。
- **接口优化**：`ReqQryInstrumentCommissionRate`：按合约查询时 Rsp 的 `InstrumentID` 为合约代码（避免误用）；新增按品种查询（InstrumentID 填品种代码时，返回该品种及该品种下不同于品种设置的单一合约费率）。`ReqQryOptionInstrCommRate`：按合约查询时 Rsp 的 InstrumentID 为合约代码。`ReqQryInstrumentMarginRate`：同手续费率，亦新增按品种查询。
- **新增** `ReqQryUserSession`（查询用户会话）。
- **登录响应**新增 `LastLoginTime`（上次登录时间）与 `ReserveInfo`（预留信息）。
- **修复**：API 连 front_se_hc 前置时，断线后收到 OnFrontDisconnected 会超时的问题。
- **结构体**：`CThostFtdcOffsetSettingField` 增 `ApplySrc`（0=交易，1=会服），影响 `OnRtnOffsetSetting`、`OnRspQryOffsetSetting`。柜台开启“查询会服自对冲数据”后数据有两个来源，会服来源的数据不能经API撤单，撤单应选 ApplySrc=0 的数据；撤会服数据会报错“CTP: 撤销对冲设置未找到记录”。

### 1.4 6.7.10（2025-04-22）
- `CThostFtdcTradingAccountField`、`CThostFtdcInvestorPositionField` 增 `OptionValue`（期权市值），涉及 OnRspQryTradingAccount、OnRspQrySecAgentTradingAccount、OnRspQryInvestorPosition。
  - 期权市值 = (多头期权手数 − 空头期权手数) × 期权合约乘数 × 期权最新价
  - 市值权益 = 期权市值 + 权益
- 新增 `RegisterWechatUserSystemInfo`（中继多连接模式，微信小程序等上报）与 `SubmitWechatUserSystemInfo`（中继操作员登录模式），参数 `CThostFtdcWechatUserSystemInfoField*`。

### 1.5 6.7.9P1（2025-03-19）
- 新增对冲设置：`ReqOffsetSetting`/`OnRspOffsetSetting`/`OnRtnOffsetSetting`/`OnErrRtnOffsetSetting`；撤销：`ReqCancelOffsetSetting`/`OnRspCancelOffsetSetting`/`OnRtnOffsetSetting`/`OnErrRtnCancelOffsetSetting`；查询：`ReqQryOffsetSetting`/`OnRspQryOffsetSetting`（ProductID 填产品则返回该产品下所有设置）。
- 填写规则：
  - 期权对冲：InstrumentID（期权合约）、UnderlyingInstrID（标的期货）、ProductID（期权产品）至少一个非空。
  - 期货对冲：InstrumentID、ProductID 选填，UnderlyingInstrID 不填。
  - 行权后对冲/履约后对冲：选填 UnderlyingInstrID、ProductID，InstrumentID 不填。
  - 合约级别的期权对冲与期货对冲且 IsOffset=true 时，Volume 须在 [1,99999999]，99999999 表示全部手数；其他情况不检查手数。
  - 同一“投资者+对冲粒度+对冲类型”后台只保留一笔；需区分每笔可用 RequestID（只回显，不检查）。

| 类型 | 品种级 | 系列级 | 合约级 | 客户级 |
|---|---|---|---|---|
| 期权对冲 | ProductID具体，UnderlyingInstrID/InstrumentID空 | ProductID空或具体，UnderlyingInstrID具体，InstrumentID空 | InstrumentID具体，Volume∈[1,99999999] | — |
| 行权后/履约后对冲 | ProductID具体，UnderlyingInstrID空 | — | UnderlyingInstrID具体（ProductID可空） | ProductID、UnderlyingInstrID空 |
| 期货对冲 | ProductID具体，InstrumentID空 | — | InstrumentID具体，Volume∈[1,99999999] | ProductID、InstrumentID空 |

- 其他：大商所期权行权接口不能再报“行权后自对冲”，`CloseFlag` 只能填 `EOCF_NotToClose('1')`，否则报错；大商所期权放弃申请使用 `ReqExecOrderInsert`；二阶段上线前“取消到期自动行权”沿用旧方式（行权接口手数为0），上线后用“期权放弃申请”。

### 1.7 6.7.8（2024-09-18）

### 1.17 6.5.1（2020-09，traderapi；后台补充说明 V6.5.2_P3）
**兼容性**：V6.5.1 API 连接后台需 ≥V6.5.0（接 6.5.0 时 6.5.1 新增接口无响应，其余正常）；6.5.1 后台兼容 <6.5.1 的旧版API。运行环境同6.6.1P1。

**变动**
1. **InstrumentID 增长**（支持大商所超长组合合约）：`TThostFtdcInstrumentIDType` 由 31(30字节有效) 改为 `char[81]`；原类型更名 `TThostFtdcOldInstrumentIDType char[31]`，旧字段改为保留字段（reserve1/reserve2/reserve3，填写被忽略）。
2. **IPAddress 增长**：`TThostFtdcIPAddressType char[33]`；旧类型 `TThostFtdcOldIPAddressType char[16]`，旧字段变保留字段(reserve2)。填写：`strcpy(address,"127.0.0.1")`；IPv6 需转成非零压缩的原始地址并去掉冒号，如 `AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHH`。前置地址：`tcp://172.24.121.51:35001`、`tcp6://fe80::20f8:aa9b:7d59:887d:35001`（RegisterFront/RegisterNameServer）。
3. **新增 `ReqQryCombPromotionParam`**（大商所组合优惠参数，InstrumentID 填组合合约代码；查询返回 CombHedgeFlag 默认投机；Xparameter 为期权组合保证金比例）。保证金公式：
   - 期权对锁 OPL：X × 卖期权保证金
   - 买入期权垂直价差 BLS：X × 卖期权保证金
   - 卖出期权垂直价差 BES：min(执行价之差 × 交易单位, 空头期权保证金)
   - 日历价差 CAS：X × 卖出期权保证金
   - 买入期权期货组合 BFO：X × 期货保证金
4. **新增组合类型枚举** `TFtdcCombinationTypeType`：`'0'` 期货组合 COMBT_Future、`'1'` 垂直价差BUL、`'2'` BER、`'3'` 跨式STD、`'4'` 宽跨式STG、`'5'` 备兑PRT、`'6'` 时间价差CAS、`'7'` 期权对锁OPL、`'8'` 买备兑BFO、`'9'` 买入期权垂直价差BLS、`'a'` 卖出期权垂直价差BES。大商所组合申请/拆分合约填写示例：
```text
STD m1905-c-2700&m1905-p-2700      期权跨式
STG m1905-p-2400&m1905-c-2700      期权宽跨式
PRT m1905-c-2400&m1905             备兑
SP  a1903&a1905                    期货跨期
SPC c1903&cs1909                   期货跨品种
SP  a1903& a1903                   期货对锁
OPL m1809-P-3150&m1809-P-3150      期权对锁
BLS m1809-P-3150&m1809-P-3100      买入垂直价差
BES m1809-P-3350&m1809-P-3150      卖出垂直价差
CAS m1807-P-3150&m1809-P-3150      日历价差
BFO m1809-P-3150&m1809             买入期权期货
```
5. **公有流可订阅/取消**：`SubscribePublicTopic(THOST_TE_RESUME_TYPE)` 增加 `THOST_TERT_NONE`（取消订阅公共流）；不调用则默认从本交易日开始订阅（以实际传参为准），须在 Init 前调用（登录前）。取值：RESTART 从本交易日开始重传；RESUME 从上次收到的续传；QUICK 只传送登录后公共流内容；NONE 取消订阅。
6. **新增 `ReqQryClassifiedInstrument`**（分类合约）：入参 InstrumentID、ExchangeID、ExchangeInstID、ProductID、`TradingType`('0'全部 TD_ALL / '1'交易 TD_TRADE / '2'非交易 TD_UNTRADE)、`ClassType`('0'所有 INS_ALL / '1'期货、即期、期转现、Tas、金属指数 INS_FUTURE / '2'期货期权、现货期权 INS_OPTION / '3'组合 INS_COMB，对应 ProductClass 组合类型）。大商所只可申请组合的合约为非交易合约。
7. **接口改名**：`ReqQueryMaxOrderVolume`→`ReqQryMaxOrderVolume`(结构 QryMaxOrderVolumeField)；`OnRspQueryMaxOrderVolume`→`OnRspQryMaxOrderVolume`。旧版API接入6.5.1后台仍可用旧名。
8. **ReqQryQuote 逻辑优化**：指定 QuoteSysID（空则返回全部）时后台按其过滤，旧后台不支持过滤。
9. **看穿式采集库**：无变动，暂只采集 IPv4。

**6.5.1 补充说明（后台 V6.5.2_P3）**
- `ReqQryInstrument` 返回不再包含大商所“不可交易、只能申请组合”的合约，减小登录查询数据量。
- `ReqQryClassifiedInstrument`：大商所可申请组合的合约以**产品级别**返回，且必须同时填 `ExchangeID='DCE'`、`TradingType='2'`、`ClassType='3'` 才返回（如 STD m2103-C-2400&m2103-P-2400 等整合为 `STD m_o&m_o` 一条）；查询所有合约须填 `TradingType='0'`、`ClassType='0'`，返回的大商所期货组合以合约级别返回（含可下套利单与只可申请组合的期货组合），**不含**可申请组合的期权组合。
- `ReqQryCombPromotionParam`：InstrumentID 须填组合合约产品级别代码（如查 BLS m2103-P-3150&m2103-P-3100 须填 `BLS m_o&m_o`），优惠比例按产品级返回；入参为空时亦按产品级返回。

## 3 新旧版 API 迁移指南

### 3.1 版本兼容矩阵

后台普遍兼容旧版本 API 接入（旧API连新后台、新API连旧front 的压缩机制均向下兼容）。运行环境：Linux Redhat 5.8+；Windows vista+（32/64位）。

### 3.2 reserve 字段与新字段（6.5.1 起）

| 变化点 | 旧版 API | 新版 API(≥6.5.1) | 迁移动作 |
|---|---|---|---|
| 合约代码类型 | `TThostFtdcInstrumentIDType char[31]`（30字节有效） | 新类型 `char[81]`（80字节有效）；旧类型更名 `TThostFtdcOldInstrumentIDType char[31]` | 重新编译；所有缓冲区/日志/数据库列加宽到 ≥81 |
| 旧合约字段 | `InstrumentID` | 变为保留字段 `reserve1`（OldInstrumentIDType）；交易所合约代码旧字段 `reserve2`（OldExchangeInstIDType）；`reserve3`（OldInstrumentIDType） | 不要读写 reserve*，**填写会被系统忽略**；改用同名新字段 InstrumentID / ExchangeInstID 等 |
| IP 地址类型 | `char[16]` | `TThostFtdcIPAddressType char[33]`；旧类型 `TThostFtdcOldIPAddressType char[16]`，旧字段变保留字段（如 reserve2） | 使用新 IPAddress 字段 |

| 登录应答 | 无后台版本/交易所时间 | 6.6.5 加 `SysVersion`；6.6.8 加 `GFEXTime`；6.7.11 加 `LastLoginTime`、`ReserveInfo` | 按需读取 |

#### 关于 reserve1 / reserve2 的含义
- “reserve*”是旧版定长字段被保留的占位，值**不再被系统读取**，输出时多数情况下也仅为旧字段兼容回填（可能被截断到 30 字节）。
- 新版合约字段：`InstrumentID`（80字节）、`ExchangeInstID`（合约在交易所的代码）、`UnderlyingInstrID`（标的合约）、`ProductID` 等；查询请求中旧的 reserve1 同理忽略。
- （工程建议）封装层统一以新字段读写，旧版 API 编译配置下用条件编译隔离，不要在业务层出现 reserve。

### 3.4 迁移检查清单
1. 用目标版本头文件与库整体重新编译（结构体布局随版本变化，禁止混用旧头文件+新库）。
2. 全部合约代码缓冲区 ≥ 81 字节，IP 缓冲区 ≥ 33 字节，系统信息采集缓冲区 ≥ 270 字节。
3. 不再读写任何 `reserve*` 字段；输入结构先整体 `memset` 为 0。
4. 重命名：`ReqQueryMaxOrderVolume` 系列 → `ReqQryMaxOrderVolume` 系列。
5. 确认后台版本 ≥ 所用新接口的引入版本，否则新接口无响应（会表现为超时）。
6. 评测与生产库/模式一致（采集库、API 的 blsProductionMode）。
7. 登录流程补充：认证 → （中继注册用户系统信息）→ 登录（必要时 SMSCode）。
8. 订阅公共流/私有流的续传方式在 Init 前设置；了解 6.7.13 的 FROM_SEQ_NO。
