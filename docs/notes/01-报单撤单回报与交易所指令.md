## A. 报单/撤单输入字段关键语义

### A1. OrderPriceType 报单价格条件

枚举（信易表实际出现的值）：

| 枚举 | 含义 | 交易所支持情况（据源文件） |
|---|---|---|
| `THOST_FTDC_OPT_LimitPrice` | 限价 | 四所全支持 |
| `THOST_FTDC_OPT_AnyPrice` | 任意价（市价） | 大商所/郑商所市价单、郑商所 FAK、大商所止损止盈均用它 |
| `THOST_FTDC_OPT_BestPrice` | 最优价 | 仅中金所市价单体系 |
| `THOST_FTDC_OPT_FiveLevelPrice` | 五档市价 | 仅中金所市价单体系 |

「四家交易所交易指令整理.pdf」市价单行原文：

- 上期所：**「生产环境暂不支持 / 有支持意向，测试环境已经测试过，生产环境支持时间不确定」**。
- 大商所：**「支持市价单录入 / 内部将市价单转成限价涨跌停板价参与撮合（成交价可能不等于对手价）」**。
- 郑商所：**「支持，最优对手价成交」**。
- 中金所：**「支持，最优对手价成交」**，且「近期新增」五类：
  1. 任意价转限价（任意价未成交部分转最新价限价单）
  2. 五档市价（与对手方五档市价尝试成交，剩余部分撤销）
  3. 五档市价转限价（与对手方五档市价尝试成交，剩余部分转最新价限价单）
  4. 最优价（与对手方最优价尝试成交，剩余部分撤销）
  5. 最优价转限价（与对手方最优价尝试成交，剩余部分转最优价限价单）

信易表对中金所市价单的字段化表述：五档市价 = `FiveLevelPrice + CC_Immediately + TC_IOC + VC_AV`；五档市价转限价 = `FiveLevelPrice + CC_Immediately + TC_GFD + VC_AV`；最优价 = `BestPrice + CC_Immediately + TC_IOC + VC_AV`；最优价转限价 = `BestPrice + CC_Immediately + TC_GFD + VC_AV`。即「撤销型」用 IOC，「转限价型」用 GFD。

### A2. TimeCondition 有效期类型

源文件中出现的值：

| 枚举 | 含义 | 使用场景 |
|---|---|---|
| `THOST_FTDC_TC_GFD` | 当日有效 | 限价单、市价单（郑商所/大商所）、止损止盈、五档/最优价转限价 |
| `THOST_FTDC_TC_IOC` | 立即成交，否则撤销 | 全部 FAK/FOK |

「四家交易所交易指令整理.pdf」特殊指令行：上期所/大商所/中金所均为 **「FAK，FOK，GFD – 当日有效」**；郑商所为 **「FOK，IOC，GFD – 当日有效」**（注意：此格与下方 D 节官方通知、信易明细互相矛盾，见 E 节坑点 8）。
GTD/GTD 等其余有效期枚举源文件未涉及（源文件未覆盖）。

### A3. VolumeCondition 成交量类型 —— FAK/FOK 的真正落点

| 枚举 | 含义 | 对应指令 |
|---|---|---|
| `THOST_FTDC_VC_AV` | 任意数量 | 限价单、FAK（任意成交数量）、市价单 |
| `THOST_FTDC_VC_CV` | 全部数量 | FOK |
| `THOST_FTDC_VC_MV` | 最小数量 | FAK（指定成交数量，即设了最小成交量的 FAK） |

信易表揭示的关键规律：**FOK/FAK 不是靠一个字段区分的，而是 TimeCondition + VolumeCondition 的组合**：

- FAK（任意成交数量）= `TC_IOC + VC_AV`
- FAK（指定成交数量，设最小成交量）= `TC_IOC + VC_MV`
- FOK = `TC_IOC + VC_CV`

「FAK 指定成交数量」仅出现在**上期所、中金所**表格中；大商所、郑商所的 FAK 只有 `VC_AV` 一种。

### A4. ContingentCondition 触发条件

| 枚举 | 含义 | 出现位置 |
|---|---|---|
| `THOST_FTDC_CC_Immediately` | 立即 | 所有普通指令 |
| `THOST_FTDC_CC_Touch` | 止损（触价） | 仅大商所，`AnyPrice + CC_Touch + GFD + AV` |
| `THOST_FTDC_CC_TouchProfit` | 止盈 | 仅大商所，`AnyPrice + CC_TouchProfit + GFD + AV` |

「四家交易所交易指令整理.pdf」止损/止盈行原文：上期所「无」；大商所「支持」——**「最新价>/<触发价（CTP 中为StopPrice）时触发新报单，新报单可以是市价单，也可以是限价单」**；郑商所 **「买止损平仓和卖止损平仓指令是数年前提出的概念，一直未实施」**；中金所「无」。
注意：止损/止盈在 CTP 中不是挂在订单上的条件，而是**触发后另下一笔新报单**。

### A5. 其他字段的覆盖情况

- `IsSwap`：大商所展期/互换据「四家交易所交易指令整理.pdf」为 **「CTP 中报单录入时 IsSwap = true」**（展期=同品种不同月份，互换=不同品种同月份）。
- `ForceCloseReason`、`HedgeFlag`、`CombHedgeFlag`、`CombOffsetFlag`：**源文件未覆盖**（仅在异常交易语境出现「套保」「套利」字样，未展开字段值），需查 CTP 结构体定义另行补充。
- `StopPrice`：即止损/止盈触发价，上文 A4。

## B. 报单回调规则（报单回调规则.pdf，CTP 6.7.2 API 说明内置文档）

### B1. 术语（原文照录）

- **报单回报**：「指报单的状态回报，有未知单报单回报、未成交报单回报、部分成交报单回报、全部成交报单回报和撤单回报。对应回调函数 OnRtnOrder，以 OrderStatus 字段区分。」
- **成交回报**：「指报单成交后推送的成交回报，对应回调函数 OnRtnTrade。」
- **错单响应**：「指报单被 CTP 拒绝后返回的响应通知，对应回调函数 OnRspOrderInsert，其中 ErrorID 和 ErrorMsg 指明了错误原因。」
- **错单回报**：「指报单被 CTP 或交易所拒绝后的报单的状态回报。对应回调函数 OnErrRtnOrderInsert。」
- 总前提：「在给定交易所报单回报顺序的前提下，CTP 返回给 API 的回调顺序是固定的。」

### B2. 七个测试场景的固定回调顺序（合约 ag1207，原文照录）

场景 1（先未成交、后全部成交 1 手）：

```
ReqOrderInsert
  OnRtnOrder（未知单）
  此时CTP接收到交易所的未成交报单回报
  OnRtnOrder（未成交）
  此时CTP接收到交易所的成交回报和全部成交报单回报
  OnRtnOrder（未成交）
  OnRtnOrder（全部成交）
  OnRtnTrade
```

场景 2（立即全部成交，「此案例没有收到交易所的未成交回报状态，而是直接收到全部成交状态」）：

```
ReqOrderInsert
  OnRtnOrder（未知单）
  此时CTP接收到交易所的成交回报和成交报单回报
  OnRtnOrder（未知单）
  OnRtnOrder（全部成交报单已提交）
  OnRtnTrade
```

场景 3（先未成交、后撤单）：

```
ReqOrderInsert
  OnRtnOrder（未知单）→ OnRtnOrder（未成交）
  ReqOrderAction
  此时CTP接收到交易所的撤单报单回报
  OnRtnOrder（未成交）
  OnRtnOrder（已撤单）
```

场景 4（报 10 手，未成交→成交 3 手→剩余 7 手全部成交）：

```
ReqOrderInsert
  OnRtnOrder（未知单）→ OnRtnOrder（未成交）
  此时CTP接收到交易所的成交回报和部分成交报单回报
  OnRtnOrder（未成交）→ OnRtnOrder（部分成交）→ OnRtnTrade
  此时CTP接收到交易所的成交回报和全部成交报单回报
  OnRtnOrder（部分成交）→ OnRtnOrder（全部成交）→ OnRtnTrade
```

场景 5（报 10 手，未成交→成交 4 手→撤剩余 6 手）：

```
ReqOrderInsert
  OnRtnOrder（未知单）→ OnRtnOrder（未成交）
  成交回报+部分成交报单回报到达：
  OnRtnOrder（未成交）→ OnRtnOrder（部分成交）→ OnRtnTrade
  ReqOrderAction
  此时CTP接收到交易所的撤单回报
  OnRtnOrder（部分成交）→ OnRtnOrder（已撤单）
```

场景 6（对已撤单委托再次撤单）：`ReqOrderAction` → `OnRspOrderAction`（"CTP:报单已全成交或已撤销，不能再撤"）→ `OnErrRtnOrderAction`（同样文案）。

场景 7（撤一笔不存在的委托）：`ReqOrderAction` → `OnRspOrderAction`（"CTP:撤单找不到相应报单"）→ `OnErrRtnOrderAction`（同样文案）。

**由场景归纳出的模式**（文档未逐条直述，为据上表归纳）：

1. 报单提交后 CTP 先推一笔「未知单」OnRtnOrder；此后交易所每来一笔状态迁移型报单回报，CTP 一般先补推一笔「前状态」OnRtnOrder、再推「新状态」OnRtnOrder（场景 1/3/4/5 均可见；场景 2 中连推两笔未知单后在全部成交）。
2. `OnRtnTrade` 总在新状态的 `OnRtnOrder` **之后**推送。
3. 撤单成功后同样遵循「前态→已撤单」两笔模式；撤单失败时 `OnRspOrderAction` 与 `OnErrRtnOrderAction` **成对出现**，先响应后回报。

### B3. 大商所特殊回调规则（原文照录）

> 「目前大商所的回报比较特殊，当一笔委托全部成交后，大商所直接返回该笔委托的成交回报，而不返回状态为全部成交的报单回报，对于这种情况，CTP 会补一个状态为全部成交的报单回报。」

大商所场景 1/2（c1911-C-1760）：`OnRtnOrder（未知单）→ OnRtnOrder（未成交）`，成交回报到达后 **`OnRtnOrder（全部成交）`（CTP 补充生成，且不重复推送前一状态）→ `OnRtnTrade`**。
大商所场景 2 特别注明：「大商所不管会不会立即成交，只要委托进入报单簿后都会返回一笔未成交报单回报给到 CTP。」
大商所场景 3（撤单）：`OnRtnOrder（未知单）→ OnRtnOrder（未成交）→ [ReqOrderAction] → OnRtnOrder（未成交）→ OnRtnOrder（已撤单）`。

### B4. OrderStatus 状态机

源文件「报单回调规则.pdf」只给出中文状态名；单字母/数字代码为 CTP 通用枚举定义（源文件未列代码，需与 ThostFtdcUserApiStruct.h 核对）：

| OrderStatus | 枚举名 | 含义 | 迁移要点 |
|---|---|---|---|
| `'a'` | Unknown | 未知单 | CTP 收到报单请求、未收到交易所确认时的初始/前态 |
| `'b'` | NotTouched | 尚未触发 | 条件单（止损止盈）未触发态，源文件未出现 |
| `'c'` | Touched | 已触发 | 条件单已触发，源文件未出现 |
| `'3'` | NoTradeQueueing | 未成交还在队列中 | 挂单在簿 |
| `'4'` | NoTradeNotQueueing | 未成交不在队列中 | 源文件未出现 |
| `'1'` | PartTradedQueueing | 部分成交还在队列中 | 部分成交后剩余仍在队列 |
| `'2'` | PartTradedNotQueueing | 部分成交不在队列中 | 源文件未出现 |
| `'0'` | AllTraded | 全部成交 | 终态 |
| `'5'` | Canceled | 撤单 | 终态 |

状态迁移（据场景归纳）：`a → 3（未成交）→ 1（部分成交）→ 0（全部成交）`，或 `… → 5（已撤单）`；立即成交时 `a → 0`。`OnRtnOrder` 会重复推前态，**不可假设每笔 OnRtnOrder 都代表一次新状态**，须以 OrderStatus 与前值比对去重。

### B5. 报单被拒绝时的回调分流

- CTP 层拒绝（如风控、字段非法）：来 `OnRspOrderInsert`（错单响应，ErrorID/ErrorMsg 指明原因）。
- CTP 或交易所拒绝后的状态回报：来 `OnErrRtnOrderInsert`（错单回报）。
- 二者是不同回调，错误处理逻辑要同时挂；仅挂 OnErrRtnOrderInsert 会漏掉 CTP 本地校验失败，仅挂 OnRspOrderInsert 会漏掉交易所拒绝（源文件未覆盖）。

### B6. LimitPrice / StatusMsg 使用约定

**源文件未覆盖**。可验证的相邻信息：报单回调规则.pdf 仅说明 OnRspOrderInsert 的 ErrorID/ErrorMsg 用途；「交易所流水号放 StatusMsg」「市价单回报 LimitPrice 为转换后限价」等常见说法需查 CTP 结构体注释或实测确认，本笔记不采信。

## C. 交易所特殊指令差异

### C1. 市价单

| 交易所 | 支持情况（四家表原文） |
|---|---|
| 上期所 | 生产环境暂不支持；测试环境已测试，生产支持时间不确定 |
| 大商所 | 支持录入，但内部转限价涨跌停板价撮合，**成交价可能不等于对手价** |
| 郑商所 | 支持，最优对手价成交 |
| 中金所 | 支持，最优对手价成交；另有五档/最优价及其转限价共 5 种 |

### C2. 止损/止盈

仅大商所支持（`CC_Touch`/`CC_TouchProfit` + `StopPrice` 触发新报单，新单可为市价或限价）。上期所、中金所无；郑商所的止损平仓类指令「数年前提出的概念，一直未实施」。

### C3. 特殊指令

- 上期所 / 大商所 / 中金所：FAK、FOK、GFD（当日有效）。
- 郑商所：四家表列「FOK，IOC，GFD」，但郑商所官方通知（郑商函〔2014〕333 号）明确只推出 FAK，科普文亦称「郑商所目前仅支持 FAK 指令」；信易明细中郑商所期货确无 FOK。**以官方通知+字段明细为准：郑商所期货仅 FAK；IOC/GFD 为基础属性而非独立指令。**
- FAK/FOK 不得在集合竞价时段使用；应结合限价（或市价）指令使用（D 节）。

### C4. 套利指令

| 交易所 | 套利支持（四家表 + 郑商函 333 号） |
|---|---|
| 上期所 | 无 |
| 大商所 | 跨期、跨品种（交易所提供规范合约）；展期（同品种不同月份）、互换（不同品种同月份）用 `IsSwap=true`；组合保证金「暂无」，未来计划期货×期货、期货×期权、期权×期权 |
| 郑商所 | 跨期、跨品种（规范合约）；另据郑商函 333 号：实施跨品种套利指令，套利指令增加「一开一平」交易方式 |
| 中金所 | 四家表未列套利；跨机构保证金计划见大商所行对照（源文件未覆盖中金所套利细节） |

## D. FAK/FOK 文件汇编细节

### D1. 定义（doc 与 wps 文字完全一致，原文）

> （一）立即全部成交否则自动撤销指令（FOK 指令），指在限定价位下达指令，如果该指令下所有申报手数未能全部成交，该指令下所有申报手数自动被系统撤销。
> （二）立即成交剩余指令自动撤销指令（FAK 指令），指在限定价位下达指令，如果该指令下部分申报手数成交，该指令下剩余申报手数自动被系统撤销。

### D2. FAK 的最小成交数量语义（原文）

> 在 FAK 指令下，可以设定最小成交数量也可以不设定最小成交数量。如果设定最小成交数量，在限定价位下达指令后，若成交的申报手数高于或等于最小成交数量，该指令下剩余申报手数自动被系统撤销；若可成交的申报手数低于最小成交数量，该指令下所有申报手数自动被系统撤销。如果不设定最小成交数量，在限定价位下达指令后，若该指令下部分申报手数成交，该指令下剩余申报手数自动被系统撤销。

对应 CTP 字段：不设最小成交量 = `TC_IOC + VC_AV`；设最小成交量 = `TC_IOC + VC_MV`（信易表中上期所/中金所的「FAK 指定成交数量」）。

### D3. 注意事项（doc 版 2 条 vs wps 版 3 条）

doc「FOK和FAK指令说明书」：
> （一）FOK 和 FAK 指令应当结合我所目前提供的**限价**指令使用。
> （二）FOK 和 FAK 指令**不得在集合竞价时段使用**。

wps「FAK和FOK到底是神马」：
> （一）FOK 和 FAK 指令应当结合各家交易所目前提供的**限价或市价**指令使用。
> （二）FOK 和 FAK 指令不得在集合竞价时段使用。
> （三）使用 FAK 和 FOK 指令造成的自成交和撤单**不计入异常交易内**。

wps 版将「限价」放宽为「限价或市价」（与信易表中郑商所 AnyPrice+IOC+AV 的 FAK 相符），并新增异常交易豁免说明。

### D4. 算例（doc 为 Cu1308，wps 为 Cu1408，数字相同）

盘口：卖一 52010 元/吨 × 15 手，卖二 52020 元/吨 × 13 手，前一成交价 52000；涨停 53130、跌停 48070。

- **FOK 买 50 手 @52020**：50 手不能全部成交（最多成交 28 手）→ 50 手买申报全部自动撤销。
- **FAK 买 50 手 @52020，不设最小成交量**：先以 52010 成交 15 手、再以 52020 成交 13 手，剩余 22 手自动撤销。
- **FAK 买 50 手 @52020，设最小成交量 30 手**：可成交仅 28 手 < 30 → 50 手全部自动撤销。

### D5. 历史与覆盖面（wps 原文）

> 上交所作为第一个迈出支持 FAK、FOK 指令的步伐的交易所……在随后的一年中，其余三家交易所也陆续开启了模式。但！是！要注意哦，郑商所目前仅支持 FAK 指令。

（文中「上交所」结合上下文指上海期货交易所。）郑商所官方口径见郑商函〔2014〕333 号：2014-12-01 起推出 FAK 指令，同批还有跨品种套利、套利「一开一平」。

### D6. FAK/FOK 与异常交易监管（三份资料交叉）

|---|---|---|---|---|
| 自成交 | 单日单合约 ≥5 次 | ≥5 次 | ≥5 次 | ≥5 次 |

## E. 与通用认知不同 / 容易踩坑的点

1. **FAK/FOK 不是「一个字段」**：CTP 里 FOK = `TC_IOC + VC_CV`，FAK = `TC_IOC + VC_AV` 或 `TC_IOC + VC_MV`；只改 VolumeCondition 不改 TimeCondition 得不到 FAK/FOK 语义。
2. **「FAK 指定成交数量」只有上期所、中金所有**（`VC_MV`）；大商所、郑商所 FAK 仅 `VC_AV`。给大商所单子填 MV 不会得到预期最小成交量保护。
3. **OnRtnOrder 会重复推前态**：同一笔报单会收到「前状态→新状态」两笔 OnRtnOrder；按回调条数计数会双倍，务必按 OrderStatus 去重。
4. **OnRtnTrade 在新状态的 OnRtnOrder 之后**，不是成交回报先行；依赖「先成交后状态」的本地状态机次序会错。
5. **大商所全部成交时，CTP 自补全部成交报单回报且不重复前态**；且大商所只要进报单簿必返未成交回报（即使立即成交）。跨所用同一套成交判定逻辑要为大商所开特例。
6. **上期所生产环境不支持市价单**（CTP 侧，测试环境已测）；郑商所/中金所市价单按最优对手价成交；大商所市价单实际按涨跌停板限价撮合，成交价可能明显偏离盘口对手价——拿市价单做「一定吃掉对手价」的假设在大商所会错。
7. **止损止盈是大商所独有，且是「触发后另下新报单」**（StopPrice 触价触发，新单可为市价或限价），不是在原单上挂条件；郑商所的「买止损平仓/卖止损平仓」从未实施。
8. **郑商所 FAK/FOK 口径互相矛盾的资料**：四家整理表写郑商所「FOK，IOC，GFD」，但郑商所官方通知、科普文、信易字段明细均表明郑商所（期货）只支持 FAK；以官方通知为准。
9. **FAK/FOK 不得在集合竞价时段使用**；doc 版注意事项说「结合限价指令」，wps 版已放宽为「限价或市价指令」——旧版说明书口径偏严。
10. **FAK 设了最小成交量反而可能全撤**：可成交手数低于最小成交量时整笔撤销（Cu 算例：28 < 30 → 全撤），不设最小成交量反而能成交 28 手。
11. **撤单失败时 OnRspOrderAction 与 OnErrRtnOrderAction 成对出现**（先响应后回报），两个都要监听；报单拒绝同理分 OnRspOrderInsert（CTP 拒绝）与 OnErrRtnOrderInsert（CTP 或交易所拒绝）。
12. **FAK/FOK 形成的自成交和撤单不计入异常交易统计**（大商所明文；上期所/郑商所同样豁免），但中金所仅豁免套利/套保编码交易——中金所程序化大量报撤仍有踩线风险（频繁报撤单 500 次/日起步）。
13. 跨期/跨品种套利单在 CTP 中走交易所规范合约代码 + 套利标记；大商所展期/互换用 `IsSwap=true`，不是新价格类型。
14. 源文件中「报单回调规则.pdf」源自 CTP 6.7.2 API 说明，其场景为固定顺序承诺的前提是「给定交易所报单回报顺序」——交易所侧顺序变化时 CTP 顺序随之变化，不要当作与交易所无关的绝对保证。
