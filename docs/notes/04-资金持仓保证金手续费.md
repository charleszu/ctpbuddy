## A. TradingAccount 各字段含义与资金恒等式（出自 P1，为核心口径）

### A1. 核心恒等式（原文引用）

| 项 | 公式 | 原文（P1） |
|---|---|---|
| 静态权益 | PreBalance + Deposit − Withdraw | "静态权益 = 上次结算准备金（PreBalance，就是昨天结算后的账户权益）+ 入金（Deposit）- 出金（Withdraw）" |
| 动态权益（= **Balance**） | 静态权益 + PositionProfit + CloseProfit + CashIn − Commission | "动态权益（Balance） = 静态权益 + 持仓盈亏（PositionProfit） + 平仓盈亏（CloseProfit） + 资金差额（CashIn，即权利金收支，期权才会用到）- 手续费（Commission）" |
| 可用资金（Available） | Balance − CurrMargin − FrozenMargin − FrozenCommission − FrozenCash − DeliveryMargin | "可用资金（Available） = 动态权益（Balance）- 保证金（CurrMargin）- 冻结的保证金（FrozenMargin） - 冻结的手续费（FrozenCommission） - 冻结的资金（FrozenCash，即冻结的权利金，期权才会用到） - 交割保证金（DeliveryMargin）" |

**精确口径警示**：CTP 的 `Balance` 字段 = **动态权益**（含当日持仓盈亏/平仓盈亏），不是"静态权益 = PreBalance+入金-出金"。实现 ledger 时 Balance 必须按上式滚算，不可与"静态权益"混淆。P1 未提 WithdrawQuota 字段。

### A2. 账户字段与持仓汇总字段的对应关系

"账户资金的数据的很多字段都是持仓的相关数据的汇总求和"（P1），当日字段"结算后会清空置零"：

| 账户字段 | 语义 | 汇总来源 |
|---|---|---|
| PositionProfit | 当日持仓盈亏（浮动） | ∑各持仓的持仓盈亏 |
| CloseProfit | 当日平仓盈亏 | ∑各持仓的平仓盈亏 |
| Commission | 当日手续费 | ∑各持仓的手续费 |
| CurrMargin | 占用保证金 | ∑各持仓的 UseMargin |
| FrozenMargin | 冻结保证金 | ∑各持仓的 FrozenMargin |
| FrozenCommission | 冻结手续费 | ∑各持仓的冻结手续费 |
| FrozenCash | 冻结资金（=冻结权利金，期权） | ∑各持仓的冻结资金 |
| CashIn | 资金差额（权利金收支，期权） | ∑各持仓的资金差额 |

注：P1 原文明确"这些按持仓汇总求和的字段，都是表示当天这个交易日的数据，结算后会清空置零。例如，持仓盈亏表示今日的持仓盈亏，手续费表示今日的手续费。"

### A3. 行情快照驱动更新（P1 §1）

| 方向 | 持仓盈亏公式 |
|---|---|
| 多头 | （最新价 − 持仓均价）× 合约数量乘数 × 持仓数量 |
| 空头 | （持仓均价 − 最新价）× 合约数量乘数 × 持仓数量 |

收到行情后先更新该合约持仓的持仓盈亏，再更新账户动态权益等资金数据。

## B. InvestorPosition / 持仓明细各字段（P1、P2）

### B1. 持仓（汇总）字段语义（P1）

| 字段 | 语义/维护规则 |
|---|---|
| PositionNum / Position | 持仓数量 = ∑持仓明细的数量 |
| TodayPosition | 今仓量 = ∑开仓日期等于今日交易日的持仓明细数量 |
| YdPosition | 上日持仓（P2 组合语境）＝ Position − TodayPosition；今/昨仓口径差异见 B3 |
| OpenVolume | 开仓量：开仓成交时 += 成交数量 |
| CloseVolume | 平仓量 = ∑持仓明细的平仓量 |
| OpenCost / 开仓成本 | ∑(持仓明细的开仓价格 × 数量 × 合约乘数) |
| OpenAmount | P1/P2 未直接给出公式；P2 称分腿"开仓成本、开仓均价、持仓成本、持仓均价、持仓盈亏、平仓金额、平仓盈亏、手续费……计算所有持仓" |
| PositionCost / 持仓成本 | ∑(持仓明细的持仓价格 × 数量 × 合约乘数)；持仓均价 = 持仓成本 ÷（持仓数量 × 合约乘数） |
| preSettlementPrice/SettlementPrice | 持仓价格口径：今仓明细持仓价 = 开仓价；昨仓明细持仓价 = 昨结算价（见 E2） |
| UseMargin | 保证金 = ∑持仓明细的保证金；单笔明细 Margin = Volume × Price × 乘数 × 合约保证金率 + Volume × 合约保证金(按手数) |
| FrozenMargin | 冻结保证金，报单时增加、成交/撤单/错单时减少 |
| LongFrozen | 多头冻结：买入开仓→多头持仓 LongFrozen += 报单量；买入平仓→空头持仓 LongFrozen += 报单量 |
| ShortFrozen | 空头冻结：卖出开仓→空头持仓 ShortFrozen += 报单量；卖出平仓→多头持仓 ShortFrozen += 报单量 |
| CloseProfit / Commission | =∑持仓明细对应值；单笔成交 = ∑各明细在该成交中的值 |

可平（可用）数量（P1，防重复平仓的关键）：
- 多头：`Position − ShortFrozen − CombShortFrozen`
- 空头：`Position − LongFrozen − CombLongFrozen`

### B2. 持仓明细单条记录字段（开仓成交时新增，P1 §5）

OpenDate = 成交交易日(TradingDay)；TradeID = 成交编号；TradeType；Direction；OpenPrice = 成交价格；Volume = 成交数量；HedgeFlag；Margin 按上式算；今仓明细的持仓价格 = 开仓成交价。

### B3. 今仓/昨仓语义与交易所差异（重要）

- "部分交易所不区分今仓和昨仓，例如大商所，但平仓一般是按先开先平来处理，即先平昨仓再平今仓，而上期所和能源中心等交易所，区分平今和平昨"（P1）
- **手续费今昨口径比持仓口径更细**：即使大商所，"合约平仓手续费率和合约平仓手续费（按手数），也是区分平今和平昨进行计算的"（P1），不能对大商所平仓统一用平昨费率，否则"算出来的手续费就会和实际的手续费有较大的偏差"。

### B4. 组合持仓字段（P2）

| 记录 | 字段取值规则 |
|---|---|
| 组合合约持仓记录 | 只计算：上日持仓、今日持仓、总持仓、开仓量、**保证金**；其平仓量、平仓盈亏、持仓成本、持仓盈亏、手续费均在分腿中算 |
| 分腿合约持仓记录 | 上日/今日/总/开仓量/平仓量 = 单一合约 + 组合合约形成持仓的总合（要区分须查持仓明细）；**保证金字段只计单一合约持仓的保证金**，组合持仓保证金存在组合记录里；但开仓成本/开仓均价/持仓成本/持仓均价/持仓盈亏/平仓金额/平仓盈亏/手续费含组合形成的持仓 |
| 组合方向 | 近期合约腿多空方向与组合一致，远期合约腿与组合相反 |

## C. 保证金计算

### C1. 期货：按合约公式（P5）

```
保证金 = (按手数保证金费 + 按金额保证金率 × 价格 × 合约乘数) × 手数
API字段： 多头保证金 = (LongMarginRatioByVolume + LongMarginRatioByMoney × Price × VolumeMultiple) × Volume
空头类似（ShortMarginRatioBy*）
```
原文："截止写这篇文章时所有期货品种按手数保证金费均为0，只设了按金额保证金率"（P5 注）。

### C2. 保证金价格类型 MarginPriceType（P5，关键）

查询：`ReqQryBrokerTradingParams` → 回调 `OnRspQryBrokerTradingParams` 的 `MarginPriceType`：

| 枚举值 | 常量 | 含义 |
|---|---|---|
| '1' | THOST_FTDC_MPT_PreSettlementPrice | 昨结算价 |
| '2' | THOST_FTDC_MPT_SettlementPrice | 最新价 |
| '3' | THOST_FTDC_MPT_AveragePrice | 成交均价 |
| '4' | THOST_FTDC_MPT_OpenPrice | 开仓价 |

规则：
- 昨仓**一律**用昨结算价计算；今仓用后台设置的 MarginPriceType 决定（P5、P1 均述）。
- "只有在最新价和成交均价这两种情况下今仓的保证金值才会随着行情波动而更新，昨仓的保证金值一直是用昨结算价计算得到，不会改变。"（P5）
- 按开仓价算：冻结时用报单价，成交后用成交价；先开先平（P5 评论区作者回复："先开先平，保证金占用是b"——a、b 各开 1 手再平 1 手后剩余 b 手，占用按 b 计算）。
- 市价单："在计算保证金冻结时，使用涨跌停价计算，计算占用保证金时，按照价格类型采用相应的价格计算。"（P5）

数值例（P5）：au2106 昨结算 391.74、乘数 1000、LongMarginRatioByMoney=0.08 → 冻结/占用 = 0.08×391.74×1000 = 31339.20。

冻结保证金（下单时，P1，以昨结算价为例）：
```
增加的冻结保证金 = 昨结算价 × 合约数量乘数 × 合约保证金率 × 报单数量 + 合约保证金(按手数) × 报单数量
```
期货公司算法不一（报单价/昨结算/最新价），可通过 ReqQryBrokerTradingParams 查询确认（P1 注 2）。期权买入开仓**不占保证金**，改为冻结权利金：权利金 = 成交(或报单)数量 × 价格 × 期权合约乘数（P1 注 3）。

### C3. 交易所保证金 vs 公司保证金（P4）

- 实际冻结/占用计算采用 `ReqQryInstrumentMarginRate` 的返回（即**公司保证金率**）。
- "ReqQryInstrument 中返回的保证金率通常是交易所保证金率，计算中并不用到。ReqQryExchangeMarginRate 和 ReqQryExchangeMarginRateAdjust 查询得到的是交易所相关的保证金率，这也只在计算中间过程中会用到。"（P4）
- 含义：Same 资金在不同公司可开仓数不同（有按交易所收、有按两倍收，P4 开头）。

### C4. 保证金优惠（P5）

| 优惠 | 规则 | 查询 |
|---|---|---|
| 上期所品种内大额单边 | 同一品种所有合约按多空分别累计保证金，只收大的一边 | `ReqQryInstrument` 返回 `MaxMarginSideAlgorithm` 判断品种是否采用；当前大单边占用用 `ReqQryInvestorProductGroupMargin` 查 |
| 中金所跨品种大单边 | IF/IH/IC 跨品种双向持仓按单边较大者收；国债期货跨品种单向大边 | — |
| 大商所/郑商所 | 普通合约双边收取；标准套利合约只收两者较高；大商所盘中申请组合成功也有大边优惠 | — |

例（P5）：资金 200,000，au2106 多 100,000 + au2102 空 80,000 → 实收 100,000；再开 au2104 空 30,000（空合计 110,000 > 多 100,000）→ 实收 110,000。

保证金率调整场景（P5）：节假日前、单边市停板、极端风险/震荡、持仓量达标、临近交割月、交易所其他规定。

> **CTPBuddy 落地状态（2026-10-03 当前）**：已实现受 `Instrument.MaxMarginSideAlgorithm` 控制的同交易所、同 `ProductID` 品种内大单边；账本占用、冻结、成交、撤单、mark-to-market 与 `ReqQryInvestorProductGroupMargin` 共用 `Ledger::product_group_margin`。未启用优惠的合约按合约独立求和。
>
> **历史复核记录（保留）**：此前核心仅把 `MaxMarginSideAlgorithm` 作为合约展示字段，账本 `used_margin` 逐笔相加，查询未接线；该品种内缺口现已补齐。跨品种映射、套利组合和仓单折抵仍未实现：现有官方合约字段只有开关，没有跨品种成员关系，不能凭交易所名称抵消 IF/IM。套保与 `InvestUnitID` 的完整账本口径不在本次大单边范围内；本次只保证查询记录不虚构跨品种/投资单元归属，不把支持边界表述为官方字段非法。
>
> **真实柜台实测**（`ctp_settlement/` 63 份含期货持仓的结算单）：64 个期货持仓汇总行中 **56 行多空共存**，且**每一行**都满足 `保证金占用 == max(多头明细保证金之和, 空头明细保证金之和)`——**56/56 精确命中，无一例外**（断言由 `tools/audit_real_accounts.py` 的 `audit_hedged_margin` 固化）。比值只有 0.5 与 0.6667 两种，正是多空 imbalance 程度的直接反映。单边持仓的 8 行则恒等于明细之和。
>
> 历史上这会导致真实账户长期持有对锁仓位时，CTPBuddy 的 `CurrMargin` 在 1:1 对锁下达到柜台的 2 倍；该数值偏差现已由品种内大单边聚合修复。真实数据量尺继续保留，用于防回归。
>
> 实现边界：抵消的**分组键是同交易所 + 品种**（P5 明确"同一品种所有合约"），不是合约——`au2102` 多 + `au2106` 空也抵消；`ReqQryInvestorProductGroupMargin` 已与 `CurrMargin` 共用同一聚合。现有官方字段没有跨品种成员关系，20241206 的 IF2412 与 IM2412 不凭名称互相抵消；套利组合、仓单折抵仍未实现。完整当前实现与边界见 DESIGN §8.7.2、知识库 §10.2 第 11 条。

### C5. 期权保证金（P3）

**归纳公式（交易所口径）**："每手卖方交易保证金 = MAX(权利金 + 交易所期权合约保证金不变部分, 交易所期权合约最小保证金)"（P3 §3.5）。不变部分 = `ExchFixedMargin`，最小保证金 = `ExchMiniMargin`，均可由 `ReqQryOptionInstrTradeCost` 查询。除上期所外其他交易所最小保证金为 0。

**投资者口径**同理，把交易所费率换成投资者费率，"每手卖方交易保证金 = MAX(权利金 + 投资者期权合约保证金不变部分, 投资者期权合约最小保证金)"，对应查询字段 `FixedMargin`/`MiniMargin`（P3 §4）。

权利金价格口径（精确，P3）：
- 昨仓：一般 = 期权合约结算价 × 期权合约乘数（昨结算价）；**上期所例外 = 收盘价与结算价的较大值**（"if(上期所，[期权合约收盘价与结算价的较大值]，[期权合约结算价]) × 期权合约乘数，这里的收盘价采用昨收盘价，结算价采用昨结算价"）。
- 新仓：价格（昨结算价/成交价）× 乘数，价格类型由 `ReqQryBrokerTradingParams` 的 `OptionRoyaltyPriceType` 决定；**委托冻结一律用昨结算价**（"上述价格选择仅针对已成交持仓，委托的冻结保证金计算时，则一律使用昨结算价"）。
- 交易时段内，公式中的标的期货结算价一律用昨结算价（郑商所/大商所/上期所）、标的指数当日收盘价用昨收盘价（中金所）。

各交易所分公式：

| 交易所 | 每手卖方交易保证金 | 备注 |
|---|---|---|
| 郑商所 / 大商所 | 权利金 + max(标的期货合约保证金 − 期权虚值额的一半, 标的期货合约保证金的一半) | 标的期货合约保证金 = [标的期货结算价×期货乘数×交易所保证金率(按金额) + 交易所保证金率(按手数)]×基础商品乘数；看涨虚值额 = Max((行权价−标的结算价)×乘数,0)，看跌反之 |
| 中金所 | 买权：权利金 + max(收盘价×乘数×调整系数 − 优惠比率×虚值额, 最低保障系数×收盘价×乘数×调整系数)；卖权：末项用执行价替代收盘价 | 虚值额按股指执行价与收盘价算；交易时段用昨收盘价 |
| 上期所 | max{ 标的期货合约的保证金 × Delta风险值 + 权利金, 期权最小保证金 × 期权合约乘数 } | 昨仓权利金 = max(昨收盘价,昨结算价)×乘数；最小保证金取昨天结算发布值 |

终端实际只需算权利金部分，后半部分因用昨价为不变量，可从 TradeAPI 查 `ExchFixedMargin`/`ExchMiniMargin`（P3 各节注 6）。

### C6. 郑商所期权组合保证金优惠（P3 §5）

1. 买入跨式或宽跨式组合，**不收保证金**。
2. 卖出跨式/宽跨式 = 卖出看涨与卖出看跌交易保证金较大者 + 另一部位权利金。
3. 备兑看涨/看跌 = 权利金 + 期货交易保证金。

期权组合代码（P3 §2.2，仅郑商所有优惠）：BUL 看涨垂直价差、BER 看跌垂直价差、STD 跨式、STG 宽跨式、PRT 备兑（如 `SR407&SR407P4300`；备兑原则上交易所盘后组合，平仓需分单腿）。

## D. 手续费计算

### D1. 期货公式与字段（P4、P1）

```
手续费 = 成交数量 × (成交价 × 合约乘数 × OpenRatioByMoney + OpenRatioByVolume)
```
P4 原文："以开仓为例，查询手续费返回结果中有两项关于开仓的字段：OpenRatioByMoney（开仓手续费率）和OpenRatioByVolume（开仓手续费），这是两种计算手续费的方法。"平仓/平今对应 `CloseRatioByMoney`/`CloseRatioByVolume`、`CloseTodayRatioByMoney`/`CloseTodayRatioByVolume`（P1 也按"开仓手续费率+开仓手续费(按手数)、平仓手续费率+平仓手续费(按手数)"两段式表述）。

单笔成交手续费（P1）：
- 开仓 = 成交价 × 成交数量 × 乘数 × 开仓手续费率 + 成交数量 × 开仓手续费(按手数)
- 平仓明细 = 成交价 × N × 乘数 × 平仓手续费率 + N × 平仓手续费(按手数)（N=该明细被平数量）

平今优惠例（P1 算例）：c2101 平昨 1.2 元/手、**平今免手续费** → 今仓明细手续费 0。

### D2. 报单手续费（P4）

`ReqQryInstrumentOrderCommRate` 查询报单申报手续费，"每报撤一次单子都会收一笔费用，目前来说这是中金所特有的"；中金所手续费 = 交易手续费 + 申报费两部分。

### D3. 期权手续费（P3 §6）

"期权手续费的计算方式同期货，只是增加了执行手续费，可以使用 ReqQryOptionInstrCommRate 查询得到相应的手续费率。"（本组文档未展开 StrikeRatio 字段细节。）

### D4. 其他注意（P4）

- 查 IF2009 可能返回品种 IF 的费率："该品种下所有合约的手续费都是一样的，所以就直接将手续费设到品种级别了"。
- 交易所手续费率在 CTP 查不到，需去交易所官网交易数据/结算参数；大商所"短线开平仓"= 今开今平。
- 最小手续费：本组 PDF 未提及（字段 OpenRatioByVolume 类"按手数"部分可表达每手固定费用）。

## E. 盈亏计算

### E1. 持仓盈亏（浮动，P1）

| 方向 | 公式 |
|---|---|
| 多头 | (最新价 − 持仓均价) × 合约数量乘数 × 持仓数量 |
| 空头 | (持仓均价 − 最新价) × 合约数量乘数 × 持仓数量 |

持仓均价 = 持仓成本 ÷（持仓数量 × 乘数）（见 B1）。

### E2. 平仓盈亏 CloseProfit：两种"持仓价格"口径（P1 §5，逐日盯市核心）

单笔持仓明细平仓盈亏（N = 该明细被平数量）：

| 方向 | 公式 |
|---|---|
| 多头明细 | (成交价 − 持仓价格) × N × 合约乘数 |
| 空头明细 | (持仓价格 − 成交价) × N × 合约乘数 |

持仓价格取法（逐日盯市）：
- 历史持仓明细（OpenDate ≠ 今日）= **昨结算价**（等价于"按结算价差"口径）
- 今日持仓明细（OpenDate = 今日）= **开仓价格**（"按开仓价差"口径）

"可以看到，今仓和昨仓的持仓价格不一样，因此算出来的持仓盈亏也是不一样的，所以持仓明细的更新需要按正确的平仓顺序来算，如果顺序错了，那么算出来的平仓盈亏也就会和实际值不相符了"（P1）。汇总：此笔平仓成交平仓盈亏 = ∑各明细平仓盈亏；持仓 CloseProfit = ∑明细 CloseProfit。

P1 算例：c2101 昨结算 3005、乘数 10，2 手昨仓(开仓 3006) + 2 手今仓(开仓 3000)，卖出平仓 3 手成交价 3004，先开先平 → 平 2 手昨仓 + 1 手今仓：
- 昨仓明细盈亏 = (3004−3005)×10×2 = **−20**；手续费 2×1.2 = 2.4
- 今仓明细盈亏 = (3004−3000)×10×1 = **+40**；手续费 0（平今免）
- 合计：平仓盈亏 20、手续费 2.4；剩余 1 手今仓，开仓成本/持仓成本 30000、均价 3000、保证金 3000×10×5% = 1500

### E3. 期权差异（P1 注 3/P3）

期权盈亏 = 期货式价差 + 权利金收支（CashIn）：买入开仓支付权利金、卖出成交收取权利金，权利金 = 数量 × 价格 × 期权合约乘数；该收支计入动态权益的 CashIn 项，保证金侧体现为买入不占保证金、卖出按 C5 公式收保证金。

## F. 组合合约持仓计算规则（P2）

### F1. 开仓生成记录

组合开仓后持仓查询生成 **3 条记录**：组合合约持仓记录 + 两条分腿记录。方向：近期腿与组合同向，远期腿反向（见 B4 表）。

### F2. 平仓原则与"打散"动作

原则："先单一后组合，先开先平"——先平单一合约头寸（先开先平），不足再平组合头寸（也先开先平）。用到组合头寸时**打散**：自身分腿组合持仓 −平仓量、+组合平仓量；组合记录持仓减少；另一条分腿组合持仓减少并**衍生出单一合约持仓**（撮合编号与原组合一致、开仓时间与原组合开仓时间一致——因此衍生持仓在后续平仓中常被优先平掉）。

P2 列举 6 种情形：单一合约平仓用单个组合头寸 / 多个组合头寸 / 组合平仓只用自身头寸 / 用其他组合头寸 / 用单一合约头寸 / 同时用其他组合与自身头寸。结论规律：衍生出的单一持仓因开仓时间早于原有单一持仓，按先开先平常先被平。

### F3. 组合冻结（P2 §三）

- 多头开仓冻结：组合记录 LongFrozen +，近月腿组合 LongFrozen +，远月腿组合 ShortFrozen +。
- 多头平仓冻结：组合记录 ShortFrozen +、可平数量减少；近月腿组合 ShortFrozen +，远月腿组合 LongFrozen +。

## G. 费率查询接口语义与「查不到」行为

### G1. ReqQryInstrumentMarginRate（P4）

参数 `CThostFtdcQryInstrumentMarginRateField`：

| 字段 | 必填性 | 说明 |
|---|---|---|
| BrokerID | 必填 | "这三个字段是一定要填的，不填的话返回值就为空" |
| InvestorID | 必填 | 同上 |
| HedgeFlag | 必填 | 投机套保标志，一般投机（THOST_FTDC_HF_Speculation） |
| InstrumentID | 选填 | **填空 → 返回客户当前持仓对应合约的保证金率**；填了 → 返回该合约费率"如果什么都不填，是不会得到所有的合约保证金率的" |

定位（P4，重要）：三个查询的分工——`ReqQryInstrumentMarginRate` = 实际冻结/占用计算所用（公司费率）；`ReqQryInstrument` 的保证金率 = 交易所费率，计算不用；`ReqQryExchangeMarginRate`/`ReqQryExchangeMarginRateAdjust` = 交易所相关，仅中间过程。

### G2. ReqQryInstrumentCommissionRate（P4）

必填 BrokerID/InvestorID；InstrumentID 选填，行为同保证金率查询。配套 `ReqQryInstrumentOrderCommRate` 查报单手续费（中金所）。期权另用 `ReqQryOptionInstrCommRate`（P3 §6）；期权交易成本（保证金不变部分/最小保证金）用 `ReqQryOptionInstrTradeCost`（P3）。

### G3. InstrumentID 为空的统一行为（P3 §7 原文）

"查询期货手续费率，期货保证金率，期权手续费率，期权交易成本……时，允许 InstrumentID 为空，这时返回该投资者所有持仓合约的相关值。"——即「查不到全部」是设计行为：空合约 = 有持仓合约全集，不是全市场合约。

### G4. 相关速查表

| 需求 | 接口 |
|---|---|
| 公司保证金率 | ReqQryInstrumentMarginRate（+BrokerID/InvestorID/HedgeFlag） |
| 保证金价格类型/期权权利金价格类型 | ReqQryBrokerTradingParams → MarginPriceType / OptionRoyaltyPriceType |
| 合约乘数/品种大单边标志 | ReqQryInstrument → VolumeMultiple / MaxMarginSideAlgorithm |
| 当前大单边占用 | ReqQryInvestorProductGroupMargin |

| 期权手续费率/期权交易成本 | ReqQryOptionInstrCommRate / ReqQryOptionInstrTradeCost |
